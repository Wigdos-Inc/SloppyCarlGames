sources are ERA, DRYAD, ARGUS, RIGOR, ED, SAGE, and MAIN (the main/orchestrating

- [2026-09-26] MAIN: bug 2 (loop drift) — the author confirmed the camera bug (bug 1) is fully fixed. Bug 2 is back to its original state.
  - **Symptom.** With the side camera, loops are perfect. With the front or back camera, drift grows loop over loop until control is partly lost.
  - **Cause** (from code reading and the math, not measured).
    - `advanceCarriedForward` carried the heading onto each new surface by projecting it onto the new plane and re-normalizing.
    - On a faceted tube, each panel fold shrinks the in-loop component by cos(fold angle) but keeps the component along the fold axis, which is the tube axis. Re-normalizing then raises the axial share on every panel: about 3.6× per loop for 16 panels.
    - So any small axial offset (a camera a few degrees off, or velocity noise) grows exponentially.
    - The side camera seeds the heading as exactly the tube axis. Projection preserves that, so there's no drift.
  - **Fix.** A minimal-rotation (parallel) transport, which keeps the heading's angle to the fold.
  - **Expected.** An off-axis camera gives a constant helix, a linear drift the player can steer against. Untested; the author tests by hand.
