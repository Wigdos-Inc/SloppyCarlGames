Running log of notable engine-touching work — not custom agents alone. Valid entry
sources are ERA, DRYAD, ARGUS, RIGOR, ED, SAGE, and MAIN (the main/orchestrating
agent acting directly, without spawning a custom agent). SAGE is responsible for
appending an entry here after any of these produces a meaningful finding or change,
including the main agent's own passes. The weekly status task reads this file and
then empties it (back to this header) after summarizing — so entries only need to

  **The fix needed two halves, and the second is the one that would have failed silently.** Deleting the branch is not enough: **void wall meshes are never enumerated by `ForEachTexturedMesh`.** They work only by inheriting a textureID their host already registered — a grid host registers a tiling surface (`default-grid::p=…`) so grid linings resolve, but a noise host registers *only* per-face canvases, so the bare `stone-block` id had **no surface entry in the registry at all** (verified by dumping `textureRegistry` first). Switching noise linings to triplanar alone would have left them sampling a texture that does not exist. So `collectTextureUsage` now walks every void wall through `collectMesh`, and the lining carries a `detail.texture` copied from its host. Safe by construction: `collectMesh` already skips meshes with `faceTextureGroups`, and `registerTextureUsage` only writes `isTerrain`/`maxSpan` when `isTerrain` is true, so re-registering a host's id cannot clobber its terrain settings. Build order checked first — `BuildVoidWalls` runs at [NewLevel.js:322](engine/v1/builder/NewLevel.js#L322), textures after.

- [2026-09-07] MAIN: **implemented the author's chosen fix for noise void-wall linings — one shared tiling canvas, still on the planar path.** After the rejected triplanar attempt above, four options were put to the author and they picked "shared canvas + resolution floor", under the standing constraint that **no option uses triplanar**.
  **Two renderer facts constrained the design and were checked before writing anything:** `Render.js` binds any textureID containing `::face=` as `CLAMP_TO_EDGE` rather than `REPEAT`, so a per-face bake *can never tile*; and the `material.textureScale` uniform is applied **only** on the triplanar path. Together those force a shared canvas to be an ordinary tiling surface id with the tile scale carried in the UVs themselves.
  So the noise branch now calls `GenerateFaceProjectedUvs` with `normalize` **false** — raw planar UVs on each group's dominant axis instead of per-face `[0,1]` — and multiplies them by `textureScale / textureBlueprint.size`. **Why that factor:** a tile covers `size / textureScale` CNU, so stone-block's 64 against lvl2's `textureScale` 2 gives one tile per 32 CNU = 2 px per CNU — *exactly* the texel density the host's own face bakes get, since those are sized `span * textureScale` with normalized UVs. The lining's noise therefore matches the host wall's scale. **This is also why the naive reading of "shared canvas" was wrong:** keeping normalized `[0,1]` UVs and merely forcing a uniform canvas size would stretch the whole image across a tiny facet, so speck scale would vary with facet size. `groupCoplanarPieces` is retained — the per-group dominant-axis choice still drives the projection.
  The second half is unchanged from the reverted attempt because **that gap is real regardless of which path linings take**: linings are not enumerated by `ForEachTexturedMesh` and only inherit an id their host registered, and a noise host registers no surface. `collectTextureUsage` now runs `collectMesh` over every lining. `collectMesh` reads `mesh.detail.texture`, so **both** branches attach it — found by a runtime throw when only the noise branch had it, and fixed by making the lining shape consistent rather than guarding the read, per `FORBIDDEN_DEFENSIVE_CHECKS`. Safe by construction: `collectMesh` skips anything with `faceTextureGroups`, and `registerTextureUsage` writes `isTerrain`/`maxSpan` only when `isTerrain` is true.
  Verified: no console errors, `gl.getError()` 0. **All six cave linings report `triplanar: false`, 0 face groups, textureID `stone-block`** — the planar path preserved as required — and a plain `stone-block` surface now exists at 64×64. The **33 non-noise linings still report triplanar, unchanged.** Registry 234 → 138 entries, face bakes 109 → 12; the cave linings previously produced canvases at 1×1, 2×1, 2×2, 3×2, 4×2, 5×4, 7×6 and 8×8, and the only sub-10px bake left is a 3×3 on another mesh. UV ranges confirm constant world scale — tunnel 2.57 tiles across ~82 units, chambers under one tile across ~30. Void gates unchanged: voids 38, hosts 39, voidwalls 39, carve hosts 5.
