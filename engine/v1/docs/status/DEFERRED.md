# Deferred Work

Explicitly deferred implementations or decisions — work that was started, considered,
or raised during a task and consciously postponed, along with who deferred it and why.

This is NOT the idea backlog (see `engine/v1/docs/todo` for that). Entries here should
only be things that came up mid-task and got pushed off, not general feature ideas.

Entries persist across weekly reports until resolved, then they are **deleted** —
not checked off, not annotated as done. SAGE sweeps this list on every `log` call
and removes what the pass resolved; any other agent may delete a resolved entry too.

## Entry format

`- [ ] [YYYY-MM-DD] Item — deferred by WHO, because REASON`

Example:

`- [ ] [2026-07-09] Camera.js CNU_SCALE calibration — deferred by ED, because it depends on render pipeline stabilizing first (see CNU_VS_WORLDUNITS.md Section 4)`

- [ ] [2026-07-29] Performance-tier gate consolidation — deferred by DRYAD, originally as premature. **Reversed on 2026-07-30**: DRYAD re-reviewed and now recommends it, on the grounds that [`performanceParticleMultiplier`](engine/v1/builder/NewParticles.js#L62) and [`GetPerformanceScatterMultiplier`](engine/v1/builder/NewScatter.js#L16) are byte-identical apart from which `CONFIG.PERFORMANCE` key they read, so a single key-parameterized helper removes real duplication with no behaviour change. `GetSimDistanceValue` is differently shaped (it maps tiers to distances, not multipliers) and is **not** part of the pair — the original "three gates" framing was wrong. **Re-analysed 2026-08-19 by main agent, which recommends *against* consolidating** — the author has not ruled yet, so this stays open. There are four `CONFIG.PERFORMANCE` tier readers, not two: the pair above, [`GetSimDistanceValue`](engine/v1/physics/Collision.js#L368), and an inline lookup in [`resolveCorrectionFrames`](engine/v1/handlers/game/Animation.js#L64) that DRYAD missed because it is an expression rather than a named function. The four differ in config key, in output table (1/0/0.5 vs 0.25/0.50/1 vs 35/60/100), and in tier-string casing — `Animations.Quality` uses lowercase `"high"`/`"medium"`/`"low"` while `TerrainScatter`, `Particles`, `SimDistance` and `RenderDistance` use capitalized `"High"`/`"Low"`. Placement was the author's stated concern, and it is diagnostic: a helper parameterized by config *key* must read `CONFIG`, which couples it to mutable global state and bars `math/` under MODULE_GROUPS' stateless clause, forcing it into `core/meta.js`; a helper parameterized by the tier *value* is genuinely pure and would sit in `math/` without argument. That the placement question dissolves under one shape and not the other is evidence the key-parameterized shape is the wrong abstraction. The useful adjacent cleanup, if ever wanted, is normalizing the `Animations.Quality` casing — smaller, and a prerequisite for any future consolidation.
