# handlers/ — Orchestration Layer

## Responsibility
Top-level state managers. Handlers orchestrate the lifecycle and update flow of all other module groups. Most engine pipelines originate here. Handlers delegate low-level work to physics/, player/, builder/, cutscene/, and math/; they coordinate results rather than implementing logic directly.

## Files

### Root (cross-cutting handlers)
- `Render.js` — The sole module permitted to display visual content to the browser. All visual pipelines — DOM UI and WebGL level rendering — end here. Consumes scene graphs produced by builders and element trees from `NewUI.js`. Entity parts are split by `collectRenderableMeshes` into three buckets: `entitiesTranslucent` first (via `isTranslucentMesh` — `displayColor.a` when present, else `material.transparent`), then `entitiesUv`/`entitiesTriplanar` for the rest (keyed on `mesh.geometry.triplanar`, which is `true` or absent, never `false`). The two opaque buckets draw via `drawMeshList` in PASS A; the translucent bucket draws last, in PASS D, through `drawTranslucentPass` — sorted back-to-front by squared camera distance (`sortBackToFront`) and drawn with `{ depthMask: false }` so overlapping translucent meshes accumulate instead of depth-rejecting one another. The water surface is a fixed anchor inside that pass: the sorted list is partitioned above/below `world.water.level` and the far side draws first, water second, near side last, with the two sides swapping according to which side of the surface the camera is on. `world.water.level` is nullable — a world with no water skips the partition and the water draw entirely and issues the sorted list in one run. Because `drawMeshList` binds one shader per call, `drawSortedRuns` issues the sorted list as runs of consecutive same-shader meshes rather than re-splitting it per shader, so global order survives a mixed uv/triplanar list. The triplanar pass binds `renderer.entityTriplanarShader` — object-space triplanar sampling of the shared baked noise canvas, blended by a screen-derivative face normal — instead of the standard UV shader, for noise-textured entity parts that would otherwise collapse to flat color at entity scale. Decals (custom textures) draw in a dedicated `drawDecalPass` via `renderer.decalShader`: a tessellated quad grid (`ensureDecalQuadBuffer`) is projected onto the underlying primitive surface in the vertex shader (`projectToSurface`, mirroring `buildSphere`/`buildCylinder`/`buildCapsule` in `builder/NewObject.js`) after `buildDecalPlacementMatrix` positions the quad in part-local space; `u_partWorld` is applied after conforming so the runtime decal transform/tint/swap animation channels stay dynamic rather than baked. `resolveDecalShapeCode(baseShapeCode, side)` substitutes a flat shape code for cylinder `top`/`bottom` decals so cap decals (e.g. a cut cross-section) project flat onto the cap instead of radially onto the rim — the shared `projectToSurface` GLSL otherwise always projects radially regardless of `local.y`; sphere/capsule projection is untouched. Pass-level uniforms (projection/view/fog/colorShift/underwater) for every textured pass are set once via the shared `configureTexturedMeshPass`; `drawDecalPass` sets per-mesh decal uniforms (`u_partWorld`/`u_shape`/`u_halfExtents`/sampler slot) once per mesh while placement/tint/texture-bind stay per-decal. Matrix composition throughout uses `MultiplyMatrix4` (`math/Matrix.js`). The WebGL2 context is created with `alpha: false` — an opaque drawing buffer — so framebuffer alpha built up by translucent blending (which can exceed the intended coverage, since `blendFunc(SRC_ALPHA, ONE_MINUS_SRC_ALPHA)` accumulates alpha too) is never read by the browser's own compositing of the canvas over the page behind it; without it, fading translucent meshes visibly picked up the page background color.

  **Skybox and distance fog.** A full-screen sky quad draws before all geometry (`drawSkyPass`, `createSkyProgram`, `ensureSkyQuad`) with `DEPTH_TEST` disabled, so it writes no depth and never occludes later geometry. `skySampleGLSL` is one shared template-literal block — `sampleSky(elevation)`, both `viewRayElevation` overloads, and the sole `u_underwater` declaration — injected into both the sky fragment shader and `createFoggedTextureFragmentShader`. Fog colour is therefore *sampled from the skybox per fragment*, indexed by view-ray elevation, so the gradient tracks camera pitch; underwater the sample resolves to `world.water.tint` instead. Stops run horizon (index 0) → zenith, evenly spaced, everything below the horizon taking stop 0; `fillSkyStops` writes only the live stops into a `SKY_STOP_LIMIT`-sized uniform array. The fog *factor* is `clamp(length(v_viewPos) / u_fogFull, 0, 1)` cubed — depth is radial (the `v_viewPos` varying), not planar, and the single `u_fogFull` uniform replaced the former `u_fogDensity`/`u_far` pair. `drawScene` computes it once per frame as `simDistance × WorldInstances.Cull × WorldInstances.Fog × (CONFIG.RENDERING.Fog[Air|Water] / 100)`, sharing the hoisted `simDistance` local with `cullRadius`. `applySkyUniforms` is the one place sky/water uniforms upload, shared by `configureTexturedMeshPass` and `drawSkyPass`; `ensureFullscreenQuad` is the shared quad factory that `ensureBlendQuad` and `ensureSkyQuad` wrap. `cameraState.far` is now referenced only by `createPerspectiveMatrix`.

  **Render matrix cache.** `renderMatrixFor(mesh)` is the single accessor for a mesh's render matrix, replacing per-call `CreateRenderMatrix(mesh.displayTransform)`. It compares the mesh's builder-populated `renderMatrixCache` snapshot (see builder.md) against the live `displayTransform` via `Vector3Matches` on all four fields and returns the cached `Float32Array` unchanged on a hit; on a miss it writes into that same array via `.set()` and updates the snapshot in place. Zero allocation on the hot path — which matters because a decal-bearing terrain mesh in a level with voids passes `drawDepthPrePass`, PASS A and `drawDecalPass` in one frame, and the old path allocated twice through `toWorldUnit()` plus a `ScaleVector3` and a fresh `Float32Array` on every one of them.

  **Render-distance culling.** `collectRenderableMeshes` drops obstacle records and terrain meshes whose `performance.rendering` is false (resolved once per tick by `handlers/game/Performance.js`), and `drawDecalPass` skips the same. Because `drawDepthPrePass` and PASS A both consume the arrays `collectRenderableMeshes` returns, those two lines gate the depth pre-pass as well. Void walls and the void stencil are **not** distance-gated — they read from `sceneGraph.voids`, which carries no flag block.

  **UI stylesheet injection.** `ApplyRootStylesheet(rootId, stylesheet)` injects a converted menu's `menu.stylesheet` content (see builder.md's `NewUI.js` HTML conversion) as one engine-owned `<style id="engine-ui-style-{rootId}">` tag per root. `UI.js`'s `CreateUI` applies it before rendering and `ClearUI` removes it; `stylesheet` is `null` for hand-authored or non-HTML-converted payloads.

  **Render scale.** `syncCanvasSize` is resolution-scale-aware: it derives the canvas backing store from `CONFIG.PERFORMANCE.Resolution` (integer percent, default `100`, see core.md) via `Math.round(clientWidth * Resolution / 100)` and compares against that scaled target rather than raw `clientWidth`, so it reallocates the drawing buffer only when the scaled size actually changes. The canvas is CSS-sized to fill the viewport inside a `fixed inset:0` root, so a sub-100 backing store is upscaled by the browser for free; `gl.viewport` and the perspective aspect ratio derive from `canvas.width`/`.height` in `drawScene` and follow with no further change. Read per frame, so the setting applies live without a level restart — unlike `FrameRate`, which is latched once in `StartLevelLoop`.

  **Instanced scatter decals.** `buildScatterInstanceBuffers` precomputes decal placement matrices and the decal-bearing batch list once (not per frame) from the static post-batching scatter data. `createScatterDecalProgram`/`buildInstancedVao` (shared with the ordinary instanced scatter draw, `includeTint` toggling the extra per-instance attribute) set up one instanced VAO per decal-bearing batch; `drawScatterDecalPass` issues one `drawElementsInstanced` call per decal per batch, reusing the batch's existing per-instance model-matrix buffer rather than uploading separate per-instance decal data. `beginDecalState`/`endDecalState` centralize the blend-state setup/teardown shared by both the per-mesh and instanced decal passes.

  **Scatter distance culling and fade.** Scatter instances are packed into `STATIC_DRAW` buffers once at level build, so distance filtering happens per instance in the **vertex shader** rather than by re-packing per frame. `scatterCullGLSL` is one shared template-literal block interpolated into both scatter vertex shaders (`createScatterProgram` and `createScatterDecalProgram`), mirroring how `decalSurfaceProjectionGLSL` is shared between the two decal shaders. It takes the instance origin from `instanceModel[3].xyz`, transforms it by `u_view` for camera-relative distance, derives `fade` by `smoothstep` over the outer `Scatter.Fade` proportion of `u_cullRadius`, and compares it against `cullHash`, a hash of the instance origin. A failing instance emits `gl_Position = vec4(0, 0, 2, 1)` and returns early — `z > w` puts the vertex outside the clip volume, so the primitive is clipped before rasterization at zero vertex and zero fragment cost. Survivors get `instanceAlpha = clamp((fade - cullHash) * 4.0, 0.0, 1.0)`, a per-instance dissolve across the last quarter of that instance's own margin, reaching zero exactly where it would be culled; the shared fragment shader's `a <= 0.01` discard removes it before it writes depth, which is what keeps unsorted translucency from occluding geometry behind it. **The block must be shared, not duplicated:** decals have to cull and fade in lockstep with the blade they sit on, and hashing the origin is what makes both programs reach the same verdict for the same instance. **The two programs apply `instanceAlpha` differently.** The main scatter program is straight-alpha and carries a per-instance tint attribute, so the fade folds into `v_tint.a`; the decal program has only a `u_tint` uniform and a premultiplied fragment (its texture uploads under `UNPACK_PREMULTIPLY_ALPHA`), so it passes `v_cullAlpha` through and multiplies the **entire** `vec4` — scaling alpha alone there would leave `rgb` unscaled against a shrinking alpha and decals would brighten as they fade. `drawScene` computes `cullRadius` once per frame as `GetSimDistanceValue().toWorldUnit() * PERFORMANCE_SCALING.SimDistance.Fractions.Scatter.Cull` and carries it on `passState`; the uniform uploads in PASS B and in `drawScatterDecalPass`.

  **GPU texture-animation compositing.** `handlers/game/Texture.js` no longer composites the hold/blend crossfade itself — it is a pure state machine that advances timers and a resumable bake and sets `blendRatio`; `Render.js`'s `blendAnimatedTextures` does the actual compositing, drawing `mix(from, to, blendRatio)` into the entry's existing GL texture through `renderer.blendFramebuffer` (a full-screen quad via `createBlendProgram`/`ensureBlendQuad`). `ensureAnimatedSources` lazily creates the two GL source textures (`from`/`to`) for a given texture id and recycles the outgoing `from` buffer as the incoming `to` on each cycle rollover (`stateEntry.pendingSurface`) rather than reallocating; `uploadTextureImage`/`ensureSceneTexture` do the actual `texImage2D`/`texSubImage2D` work. `blendAnimatedTextures` runs in `drawScene` immediately after `syncCanvasSize` and *before* `gl.viewport` — the viewport/depth/blend state already set up after that call restores everything the blend pass changes, so there is no explicit restore and moving the call breaks it. It skips ids absent from `renderer.textures` (never drawn, so nothing samples the target) and entries whose bootstrap bake has not landed yet.

  **Debug overlay categories.** `boundingBoxTypeColors`, `detailedBoundsTypeColors`, and `trailTypeColors` are dictionary lookups keyed by `classifyEntityTrailType`/`classifyEntityType`'s output string; adding a category (e.g. the `Particle` bucket, distinct from `Entity`/`Enemy`) needs exactly one `CONFIG.DEBUG.LEVELS` flag (see core.md) plus one color-table entry here — no other site participates.
- `Controls.js` — Input router. Attaches to DOM events, routes keyboard and pointer input to the active context (level, UI, or game passthrough). Exports `Controls` class and `StartInputRouter`.
- `Sound.js` — Sound manager. Loads, plays, and controls all audio: music, SFX, voice, cutscene audio. Exports granular play/pause/stop/volume functions surfaced through the ENGINE API.
- `UI.js` — UI state manager. Applies UI payloads to the screen, manages screen transitions, wraps `Render.js` for UI rendering and `NewUI.js` for element construction. Exposes `ConvertHTML` (thin wrapper over `NewUI.js`'s `ParseHTML`) on the `UI` API namespace. `CreateUI` applies a payload's `menu.stylesheet` via `Render.js`'s `ApplyRootStylesheet` before rendering; `ClearUI` removes it. Three engine-owned payloads call `CreateUI` directly, bypassing `normalizePayloadSchema` — `Bootup.js`'s startup overlay, `Splash.js`'s splash steps, `Simulator.js`'s HUD — and each authors `stylesheet: null` explicitly, since without it the key would read `undefined` and inject a `<style>` tag containing the literal string `"undefined"`.
- `Cutscene.js` — Cutscene handler. Drives both engine cutscenes and pre-rendered (video) cutscenes. Coordinates the `cutscene/` module group.

### handlers/game/ (in-game state handlers)
- `Level.js` — Level lifecycle and orchestration. The main game loop. Receives validated/normalized level payloads, builds the scene via `builder/NewLevel.js`, runs the per-frame update loop: performance flags, player update, physics pipeline, enemy behavior, collectible pickups, camera update, entity animation, and rendering. `UpdatePerformanceFlags(sceneGraph)` runs once per tick at the very top of `Update`, before the Simulator early-return.

  **Fixed-timestep loop.** The accumulator loop is bounded by a **substep count** (`PERFORMANCE_SCALING.Loop.MaxSubsteps`, 4), not by a frame-time clamp — the former `levelLoop.maxFrameTime` is gone. Unsimulated debt past the cap is dropped by clamping the accumulator back to one `fixedTimeStep`, so time dilates instead of compounding into a spiral. Hitting the cap logs a `warn` on the first frame of an episode and escalates to an `error` after `sustainedCapFrames` (10) consecutive capped frames; `levelLoop.cappedStreak` tracks the run and resets on any uncapped frame. Accumulation, stepping and render all sit inside one `!levelLoop.paused` block. `fixedTimeStep` is latched from `CONFIG.PERFORMANCE.FrameRate` once in `StartLevelLoop`. `SpawnIntoScene(definition, objectType, sceneGraph)` dispatches on `objectType` — entities (`ENTITY_TYPES`) through `BuildEntity`, `"obstacle"` through `BuildObstacles`, `"terrain"` through `BuildTerrain` (role `"terrain"`, replacing an earlier untagged `BuildObject` fallback that mis-tagged terrain), anything else through the raw `BuildObject` path — passing `sceneGraph.visualResources.textureRegistry` as the `faceTextureStore` (new face textures dedup against already-resident entries) and `sceneGraph.partGeometryCache` to `BuildEntity` for geometry reuse across same-blueprint spawns; every branch funnels through a shared `finalizeSpawn(result, objectType, sceneGraph)` tail (`AddToVisualResources`, `AddTextureAnimationEntries`, conditional `RefreshSceneBoundingBoxes`). `DespawnFromScene(target, objectType, sceneGraph)` mirrors the dispatch (entities/obstacles/terrain arrays) and accepts either a single record or an array, for multi-part terrain. `ResumeLevelLoop()` calls `UpdateInputEventTypes({ payloadType: "level" })`, mirroring the identical call `CreateLevel()` makes — both restore level-mode input routing (keydown/keyup/pointerdown/mousemove/wheel) after `ApplyMenuUI` has switched global routing to UI mode (click/pointerover/pointerout only) for a menu display; without it on resume, player movement and camera input stayed dead for the rest of the session after any UI-driven pause/resume cycle. Also owns the particle runtime: `updateParticles` drives every group's lifetime once per frame (splicing finished groups inside its reverse-index loop) and `SpawnParticles(request, generator)` is the game-facing entry point re-exported as `ENGINE.Level.SpawnParticles`. `findSceneTarget(sceneGraph, id, partId)` is the short-circuiting lookup that flattens the three collections' differing shapes into `{ type, transform }` for the runtime validator and for generator-mode `SpawnParticles` resolution. `shouldRefreshBoundingBoxes` enumerates both `CONFIG.DEBUG.LEVELS.BoundingBox` and `.DetailedBounds` flag groups via `Object.entries`/`Object.values` (excluding the nested `Grid` config object) rather than a hardcoded flag list, so it self-maintains as debug categories are added — it previously tested only `BoundingBox.*` and never `DetailedBounds.*`, which could leave `debug.detailedBounds` frozen at level-build state under some flag combinations. `syncEntityMeshes` is now just an `if (entity.type === "player") return` guard followed by an unconditional `UpdateEntityModelFromTransform(entity)` call per entity — `UpdateEntityModelFromTransform` itself now short-circuits when the entity hasn't moved (see `NewEntity.js` in builder.md), so the per-frame cost this function pays scales with how many entities actually moved, not with total entity count.
- `Camera.js` — Camera state for in-game levels. Two modes: **FreeCam** (debug only; requires both `CONFIG.DEBUG.ALL` and `CONFIG.DEBUG.LEVELS.FreeCam`; WASD/arrow-key flight, mouse look via pointer lock, scroll-wheel speed tuning via `applyTuningStep`, position persisted per level/stage key across same-session level visits) and **DefaultCam** (third-person orbit follow; yaw/pitch via mouse drag or arrow keys, obstruction detection against terrain/obstacles/void walls with smooth pull-in distance interpolation). `GetCameraVectors` returns the latest cached `{ forward, right }` for player movement orientation. Exports `InitializeCameraState`, `UpdateCameraState`, `HandleFreeCamInput`, `HandleDefaultCamInput`, `GetCameraVectors`, and `SetDefaultCamFraming({ distance, heightOffset })`, which retargets DefaultCam's follow distance/height at runtime without external code reaching into camera internals — used solely by `Simulator.js` to fit framing to whatever object is currently loaded.

  **Obstruction test.** `checkCameraObstruction` builds a local AABB spanning the camera boom segment and runs `BroadphaseCollectCandidates` over it (imported from `physics/Collision.js`), rather than walking terrain, obstacles and void walls by hand — it was the only engine site running triangle-soup narrowphase against every level object every frame with no broadphase reject. Narrowphase then dispatches per candidate type: `voidWall` uses `RayAABBIntersect` purely as a gate and calls `RayDetailedBoundsIntersect` directly (the origin can sit inside the AABB, so there must be no exit-t cap), everything else goes through `RayAABBDetailedBoundsIntersect`. Three filters follow, in order: a hit flagged `inside` is discarded (the head is inside that volume, so nothing is between it and the camera — see math.md's ray-hit contract); the usual `t > 0` / closest-so-far check; and finally, for non-`voidWall` candidates, `IsPointInSuppressingVoid` on the world hit point, so host surface carved away by a void is not treated as an obstruction while real wall geometry still is. The suppression test runs *after* hit validity, so the point is only computed for hits that would otherwise be accepted.

  **`desiredPos` and `finalPos` must describe the same sphere** around `targetPoint`. `updateDefaultCamState` applies `cos(pitch)` to `desiredPos`'s X and Z components; dropping that factor (as a refactor once did) leaves `desiredPos` off the sphere at `d·√(1 + sin²pitch)`, so the obstruction ray both overshoots and points along a different line than the real boom — and since `clippedDistance` is measured along that ray and then consumed as the *radius* by `finalPos`, obstruction distances silently stop meaning what the placement uses them for. The error is invisible at pitch 0 and grows with pitch.
- `Animation.js` — Entity animation handler. Drives animation state transitions for non-player entities based on their current state each frame. `CONFIG.PERFORMANCE.Animations` is a flat tier (no sibling `Active` boolean — off is the `Disabled` tier value, which returns early from the update): `resolveCorrectionFrames` scales the per-entity correction-frame budget by `PERFORMANCE_SCALING.Animation.Entities`, clamped to 4–8 frames for the player and 0–4 for everything else.
- `Performance.js` — Per-instance performance flag resolution. `UpdatePerformanceFlags(sceneGraph)` runs once per tick from the top of `Level.js`'s `Update` and is the single site that measures camera distance for gating: it writes `performance.physics` on entities (centre distance, via `IsBeyondSimDistance`) and `performance.rendering` on terrain meshes, obstacle records and entities. The rendering test is **point-to-AABB** (`Vector3SqDistanceToAabb`, 0 inside), compared against `GetSimDistanceValue().value × PERFORMANCE_SCALING.SimDistance.Fractions.WorldInstances.Cull` squared. Consumers — `Level.js`'s entity pass, `Collectible.js`'s pickup pass, `physics/Collision.js`'s `DetectCombatOverlaps`, and `Render.js`'s render lists and decal pass — read the boolean instead of recomputing distance themselves. Builders attach the flag block, so every instance carries it from construction and no consumer guards for it. An entity's `performance.rendering` is written but has no consumer yet — entity parts are still collected for drawing unconditionally.
- `Enemy.js` — Enemy behavior handler. Per-frame enemy AI and collision response.
- `Collectible.js` — Collectible item behavior. Pickup detection and item state management.
- `Boss.js` — Boss behavior handler.
- `Simulator.js` — Simulator mode lifecycle and live scene preview orchestration. Integrated with Level.js via `IsSimulatorActive` and `UpdateSimulator`. `Load` resets `sceneGraph.partGeometryCache` to a fresh `Map` on each load so edited blueprints under a stable id always rebuild their geometry. The preview disc platform and DefaultCam framing both derive from the loaded object's AABB rather than being fixed: `spawnPlatform(sceneGraph, footprintXZ)` rebuilds the disc through the ordinary terrain spawn path (`SpawnIntoScene`, cloned from `templateDisc` with `dimensions.x`/`z` overridden); `frameLoadedObject(aabb)` sets `distance`/`heightOffset` via `SetDefaultCamFraming`, each floored at the template's authored value with `Math.max` (`framingFactor` 1.8 × the AABB's largest extent; `heightFraction` 0.5 × its height), and recomputes `followTarget` as `{ transform: { position } }` from the AABB's XZ center at its min Y — a plain object, not a scene entity, since the loaded object is stationary and needs no live re-resolution. `Load` spawns the platform *before* an obstacle/entity so grounding has a surface to key off, then re-seats the built object onto the platform: obstacles (which have no self-grounding step) get `deltaX`/`deltaY`/`deltaZ` snapping their AABB center onto the platform's top-center, applied per-part via `UpdateObjectWorldAabb` and re-merged with `MergeAabb`/`CreateDetailedBoundsFromParts`; entities have their `transform.position.x`/`z` written straight onto the platform's position (Y is already correct via the surface map) and re-posed with `UpdateEntityModelFromTransform` — needed because an authored level position, or a `BuildEntity` movement-path teleport (`movement.speed > 0`), otherwise carries the model off the disc in X/Z. Loading terrain drops the disc entirely (`objectType === "terrain"` despawns `platformMesh` and routes through `BuildTerrain`); loading anything else resizes the platform to the new object's footprint (`platformPadFactor` 1.6×) after framing. Generator requests for the loaded object are (re)built every `Load` via `ParticleGeneratorRequests(carrier, kind)` — the same function `NewLevel.js` uses, so target keys and origin math match — with every request's `physics` override forced to `"none"` (the Simulator runs no physics pipeline, so anything else would emit and never move) via `WithParticleOverride`, and fed to `SpawnParticleRequests`. `clearParticles(sceneGraph)` runs first on every `Load`/`Clear` — it despawns every entity carrying a non-null `particle`, since a reload of the *same* id would otherwise find its old groups still live (they never orphan: their target is the object being replaced, not removed) and stack duplicate emitters.
- `Texture.js` — Animated texture state manager. A pure state machine — it holds no canvas and performs no compositing itself; `Render.js`'s `blendAnimatedTextures` does the GPU crossfade (see handlers.md above). Per animated texture entry (`createAnimationStateEntry`), tracks a hold/blend phase cycle across `fromSurface`/`toSurface`/a `readySurface` lookahead, and each frame calls `builder/NewTexture.js`'s `AdvanceNoiseBake` on a resumable `bakeJob` (`BeginTextureBake`) budgeted by elapsed milliseconds (`updateTextureAnimationEntry`) rather than a predicted frame count, so a slow frame draws more and the bake still lands on schedule — this is what makes the per-face noise speck-count cap safe to lift (see builder.md). A bake always runs for whichever of the three surface slots is free; one that overruns its window stretches the animation cycle instead of spiking. `dirty` no longer exists — nothing needs to signal a re-upload since `Render.js` owns the GL texture directly. `AddTextureAnimationEntries` registers newly spawned textures mid-session without reinitializing the whole map. Exports `InitializeTextureAnimation`, `UpdateTextureAnimation`, `AddTextureAnimationEntries`.

  **Two independent gates, one per cost.** *Distance gates the CPU bake.* Each entry holds `ownerMeshes`, resolved once at entry creation by `assignOwnerMeshes` walking `NewTexture.js`'s shared `ForEachTexturedMesh` enumeration (see builder.md) — so a moving entity's owner tracks for free — and `UpdateTextureAnimation` skips both `AdvanceNoiseBake` and the `BeginTextureBake` restart when no owner is within `GetSimDistanceValue().value * PERFORMANCE_SCALING.SimDistance.Fractions.TextureAnimation.StopBake`. Distance is **point-to-AABB** (`math/Vector3.js`'s shared `Vector3SqDistanceToAabb` clamps the camera into the owner's `worldAabb`, yielding 0 inside — the same helper `Performance.js` uses), not centre distance: `sea-surface` is a large plane whose centre can sit far from a player standing on it. Owners are an **array**, and `isOwnerWithinReach` returns true if *any* owner is near — per-face texture ids are signature-shared, so several meshes can legitimately own one animated texture, and a single-owner model gated the bake on an arbitrary one. *Visibility gates the GPU blend.* `Render.js`'s `ensureSceneTexture` records every bound id into `renderer.drawnTextures` — one line at the single choke point every bind already flows through — and `blendAnimatedTextures` skips ids absent from it. The set is cleared **immediately after** the blend call (which itself runs before the mesh passes), so this frame's binds feed the next frame's decision; clearing at end of frame would gate every animated texture off permanently and not clearing would gate nothing, both silently, which is what makes that ordering load-bearing. Only the two bake calls are gated — `elapsedMs`, the hold→blend transition and `blendRatio` stay outside, so a far but visible texture finishes its in-flight crossfade and settles on `toSurface` instead of freezing mid-motion. With owners in an array, a texture resolving to *no* owner no longer throws; it silently never bakes (a scatter batch texture registers by batch id rather than through a mesh, so it lands there).

### handlers/menu/ (menu state handlers)
- `Splash.js` — Splash screen sequence management. Coordinates with `Bootup.js` for the startup splash flow via `AcceptSplashPayload` and `ApplySplashScreenSequence`.
- `LoadScreen.js` — Loading screen display logic.
- `Credits.js` — Credits screen UI and behavior.

## Boundaries
**Called by:** `Bootup.js` and `ini.js` for initialization; game code via the `ENGINE` API at runtime.  
**Calls into:** `player/`, `physics/`, `builder/`, `cutscene/`, `math/`, `core/`.  
**Does not:** Implement physics math, mesh construction, or vector math directly — these are always delegated to the appropriate group.

## Invariants
- `Render.js` is the exclusive rendering boundary. No other module writes to the DOM or WebGL context for display purposes.
- `Level.js` owns the main game loop (`requestAnimationFrame`) and is the single entry point for all per-frame game state updates.
- `SpawnParticles` is **push-only**, and must stay so. `SendEvent` dispatches synchronously from inside `Update`'s `sceneGraph.entities.forEach`, so a game's event handler — and therefore any `ENGINE.Level.*` call it makes — runs re-entrantly mid-iteration. `forEach` skips elements appended during iteration, which makes a push safe; a splice from that position would not be.
- A **runtime** particle spawn must register its textures (`finalizeSpawn` with objectType `"entity"`); the reseed path inside `updateParticles` must not. Particle parts always carry the literal `"none"` texture id, which only reaches `visualResources.textureRegistry` at build time because `NewLevel.js` pushes groups into `entities` before `PrepareLevelVisualResources` runs — so in a level with no level-authored generator that entry does not exist, and `Render.js` dereferences it unguarded. `"particle"` is never a valid `objectType` here: `ENTITY_TYPES` omits it and the fallback branch assumes a terrain-shaped record.
- `ENGINE` (assembled by `ini.js`) is the exclusive interface between game code and the engine. Game code does not import engine modules directly.
- `handlers/game/Level.js` is the direct caller of `physics/Master.js`. There is no intermediary Physics handler file in the current source.
