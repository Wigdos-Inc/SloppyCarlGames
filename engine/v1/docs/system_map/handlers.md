# handlers/ — Orchestration Layer

## Responsibility
Top-level state managers. Handlers orchestrate the lifecycle and update flow of all other module groups. Most engine pipelines originate here. Handlers delegate low-level work to physics/, player/, builder/, cutscene/, and math/; they coordinate results rather than implementing logic directly.

## Files

### Root (cross-cutting handlers)
- `Render.js` — The sole module permitted to display visual content to the browser. All visual pipelines — DOM UI and WebGL level rendering — end here. Consumes scene graphs produced by builders and element trees from `NewUI.js`. Entity parts are split by `collectRenderableMeshes` into three buckets: `entitiesTranslucent` first (via `isTranslucentMesh` — `displayColor.a` when present, else `material.transparent`), then `entitiesUv`/`entitiesTriplanar` for the rest (keyed on `mesh.geometry.triplanar`, which is `true` or absent, never `false`). The two opaque buckets draw via `drawMeshList` in PASS A; the translucent bucket draws last, in PASS D, through `drawTranslucentPass` — sorted back-to-front by squared camera distance (`sortBackToFront`) and drawn with `{ depthMask: false }` so overlapping translucent meshes accumulate instead of depth-rejecting one another. The water surface is a fixed anchor inside that pass: the sorted list is partitioned above/below `world.waterLevel` and the far side draws first, water second, near side last, with the two sides swapping according to which side of the surface the camera is on. Because `drawMeshList` binds one shader per call, `drawSortedRuns` issues the sorted list as runs of consecutive same-shader meshes rather than re-splitting it per shader, so global order survives a mixed uv/triplanar list. The triplanar pass binds `renderer.entityTriplanarShader` — object-space triplanar sampling of the shared baked noise canvas, blended by a screen-derivative face normal — instead of the standard UV shader, for noise-textured entity parts that would otherwise collapse to flat color at entity scale. Decals (custom textures) draw in a dedicated `drawDecalPass` via `renderer.decalShader`: a tessellated quad grid (`ensureDecalQuadBuffer`) is projected onto the underlying primitive surface in the vertex shader (`projectToSurface`, mirroring `buildSphere`/`buildCylinder`/`buildCapsule` in `builder/NewObject.js`) after `buildDecalPlacementMatrix` positions the quad in part-local space; `u_partWorld` is applied after conforming so the runtime decal transform/tint/swap animation channels stay dynamic rather than baked. Pass-level uniforms (projection/view/fog/colorShift/underwater) for every textured pass are set once via the shared `configureTexturedMeshPass`; `drawDecalPass` sets per-mesh decal uniforms (`u_partWorld`/`u_shape`/`u_halfExtents`/sampler slot) once per mesh while placement/tint/texture-bind stay per-decal. Matrix composition throughout uses `MultiplyMatrix4` (`math/Matrix.js`). The WebGL2 context is created with `alpha: false` — an opaque drawing buffer — so framebuffer alpha built up by translucent blending (which can exceed the intended coverage, since `blendFunc(SRC_ALPHA, ONE_MINUS_SRC_ALPHA)` accumulates alpha too) is never read by the browser's own compositing of the canvas over the page behind it; without it, fading translucent meshes visibly picked up the page background color.
- `Controls.js` — Input router. Attaches to DOM events, routes keyboard and pointer input to the active context (level, UI, or game passthrough). Exports `Controls` class and `StartInputRouter`.
- `Sound.js` — Sound manager. Loads, plays, and controls all audio: music, SFX, voice, cutscene audio. Exports granular play/pause/stop/volume functions surfaced through the ENGINE API.
- `UI.js` — UI state manager. Applies UI payloads to the screen, manages screen transitions, wraps `Render.js` for UI rendering and `NewUI.js` for element construction.
- `Cutscene.js` — Cutscene handler. Drives both engine cutscenes and pre-rendered (video) cutscenes. Coordinates the `cutscene/` module group.

### handlers/game/ (in-game state handlers)
- `Level.js` — Level lifecycle and orchestration. The main game loop. Receives validated/normalized level payloads, builds the scene via `builder/NewLevel.js`, runs the per-frame update loop: player update, physics pipeline, enemy behavior, collectible pickups, camera update, entity animation, and rendering. `SpawnIntoScene(definition, objectType, sceneGraph)` dispatches on `objectType` — entities (`ENTITY_TYPES`) through `BuildEntity`, `"obstacle"` through `BuildObstacles`, `"terrain"` through `BuildTerrain` (role `"terrain"`, replacing an earlier untagged `BuildObject` fallback that mis-tagged terrain), anything else through the raw `BuildObject` path — passing `sceneGraph.visualResources.textureRegistry` as the `faceTextureStore` (new face textures dedup against already-resident entries) and `sceneGraph.partGeometryCache` to `BuildEntity` for geometry reuse across same-blueprint spawns; every branch funnels through a shared `finalizeSpawn(result, objectType, sceneGraph)` tail (`AddToVisualResources`, `AddTextureAnimationEntries`, conditional `RefreshSceneBoundingBoxes`). `DespawnFromScene(target, objectType, sceneGraph)` mirrors the dispatch (entities/obstacles/terrain arrays) and accepts either a single record or an array, for multi-part terrain. Also owns the particle runtime: `updateParticles` drives every group's lifetime once per frame (splicing finished groups inside its reverse-index loop) and `SpawnParticles(request, generator)` is the game-facing entry point re-exported as `ENGINE.Level.SpawnParticles`. `findSceneTarget(sceneGraph, id, partId)` is the short-circuiting lookup that flattens the three collections' differing shapes into `{ type, transform }` for the runtime validator and for generator-mode `SpawnParticles` resolution.
- `Camera.js` — Camera state for in-game levels. Two modes: **FreeCam** (debug only; requires both `CONFIG.DEBUG.ALL` and `CONFIG.DEBUG.LEVELS.FreeCam`; WASD/arrow-key flight, mouse look via pointer lock, scroll-wheel speed tuning via `applyTuningStep`, position persisted per level/stage key across same-session level visits) and **DefaultCam** (third-person orbit follow; yaw/pitch via mouse drag or arrow keys, obstruction detection against terrain/obstacles/void walls with smooth pull-in distance interpolation). `GetCameraVectors` returns the latest cached `{ forward, right }` for player movement orientation. Exports `InitializeCameraState`, `UpdateCameraState`, `HandleFreeCamInput`, `HandleDefaultCamInput`, `GetCameraVectors`, and `SetDefaultCamFraming({ distance, heightOffset })`, which retargets DefaultCam's follow distance/height at runtime without external code reaching into camera internals — used solely by `Simulator.js` to fit framing to whatever object is currently loaded.
- `Animation.js` — Entity animation handler. Drives animation state transitions for non-player entities based on their current state each frame.
- `Enemy.js` — Enemy behavior handler. Per-frame enemy AI and collision response.
- `Collectible.js` — Collectible item behavior. Pickup detection and item state management.
- `Boss.js` — Boss behavior handler.
- `Simulator.js` — Simulator mode lifecycle and live scene preview orchestration. Integrated with Level.js via `IsSimulatorActive` and `UpdateSimulator`. `Load` resets `sceneGraph.partGeometryCache` to a fresh `Map` on each load so edited blueprints under a stable id always rebuild their geometry. The preview disc platform and DefaultCam framing both derive from the loaded object's AABB rather than being fixed: `spawnPlatform(sceneGraph, footprintXZ)` rebuilds the disc through the ordinary terrain spawn path (`SpawnIntoScene`, cloned from `templateDisc` with `dimensions.x`/`z` overridden); `frameLoadedObject(aabb)` sets `distance`/`heightOffset` via `SetDefaultCamFraming`, each floored at the template's authored value with `Math.max` (`framingFactor` 1.8 × the AABB's largest extent; `heightFraction` 0.5 × its height), and recomputes `followTarget` as `{ transform: { position } }` from the AABB's XZ center at its min Y — a plain object, not a scene entity, since the loaded object is stationary and needs no live re-resolution. `Load` spawns the platform *before* an obstacle/entity so grounding has a surface to key off, then re-seats the built object onto the platform: obstacles (which have no self-grounding step) get `deltaX`/`deltaY`/`deltaZ` snapping their AABB center onto the platform's top-center, applied per-part via `UpdateObjectWorldAabb` and re-merged with `MergeAabb`/`CreateDetailedBoundsFromParts`; entities have their `transform.position.x`/`z` written straight onto the platform's position (Y is already correct via the surface map) and re-posed with `UpdateEntityModelFromTransform` — needed because an authored level position, or a `BuildEntity` movement-path teleport (`movement.speed > 0`), otherwise carries the model off the disc in X/Z. Loading terrain drops the disc entirely (`objectType === "terrain"` despawns `platformMesh` and routes through `BuildTerrain`); loading anything else resizes the platform to the new object's footprint (`platformPadFactor` 1.6×) after framing. Generator requests for the loaded object are (re)built every `Load` via `ParticleGeneratorRequests(carrier, kind)` — the same function `NewLevel.js` uses, so target keys and origin math match — with every request's `physics` override forced to `"none"` (the Simulator runs no physics pipeline, so anything else would emit and never move) via `WithParticleOverride`, and fed to `SpawnParticleRequests`. `clearParticles(sceneGraph)` runs first on every `Load`/`Clear` — it despawns every entity carrying a non-null `particle`, since a reload of the *same* id would otherwise find its old groups still live (they never orphan: their target is the object being replaced, not removed) and stack duplicate emitters.
- `Texture.js` — Animated texture state manager. Per animated texture entry, tracks a hold/blend phase cycle: hold waits for `holdDurationMs`, then generates a new target surface (`BuildNoiseFaceCanvas` for face textures, `BuildTextureSurface` for all others) and blends alpha from the previous surface to the new one over `blendDurationMs`. Blend progress is written back to `textureEntry.source` each frame; `dirty` is set so the renderer re-uploads the canvas. `AddTextureAnimationEntries` registers newly spawned textures mid-session without reinitializing the whole map. Exports `InitializeTextureAnimation`, `UpdateTextureAnimation`, `AddTextureAnimationEntries`.

### handlers/menu/ (menu state handlers)
- `Splash.js` — Splash screen sequence management. Coordinates with `Bootup.js` for the startup splash flow via `AcceptSplashPayload` and `ApplySplashScreenSequence`.
- `LoadScreen.js` — Loading screen display logic.
- `Credits.js` — Credits screen UI and behavior.

## Boundaries
**Called by:** `Bootup.js` and `ini.js` for initialization; game code via the `ENGINE` API at runtime.  
**Calls into:** `player/`, `physics/`, `builder/`, `cutscene/`, `math/`, `core/`.  
**Does not:** Implement physics math, mesh construction, or vector math directly — these are always delegated to the appropriate group.

## Invariants
- `Render.js` is the exclusive rendering boundary. No other module writes to the DOM or WebGL context for display purposes.
- `Level.js` owns the main game loop (`requestAnimationFrame`) and is the single entry point for all per-frame game state updates.
- `SpawnParticles` is **push-only**, and must stay so. `SendEvent` dispatches synchronously from inside `Update`'s `sceneGraph.entities.forEach`, so a game's event handler — and therefore any `ENGINE.Level.*` call it makes — runs re-entrantly mid-iteration. `forEach` skips elements appended during iteration, which makes a push safe; a splice from that position would not be.
- A **runtime** particle spawn must register its textures (`finalizeSpawn` with objectType `"entity"`); the reseed path inside `updateParticles` must not. Particle parts always carry the literal `"none"` texture id, which only reaches `visualResources.textureRegistry` at build time because `NewLevel.js` pushes groups into `entities` before `PrepareLevelVisualResources` runs — so in a level with no level-authored generator that entry does not exist, and `Render.js` dereferences it unguarded. `"particle"` is never a valid `objectType` here: `ENTITY_TYPES` omits it and the fallback branch assumes a terrain-shaped record.
- `ENGINE` (assembled by `ini.js`) is the exclusive interface between game code and the engine. Game code does not import engine modules directly.
- `handlers/game/Level.js` is the direct caller of `physics/Master.js`. There is no intermediary Physics handler file in the current source.
