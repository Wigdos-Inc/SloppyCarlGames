# handlers/ — Orchestration Layer

## Responsibility
Top-level state managers. Handlers orchestrate the lifecycle and update flow of all other module groups. Most engine pipelines originate here. Handlers delegate low-level work to camera/, physics/, player/, builder/, cutscene/, and math/; they coordinate results rather than implementing logic directly.

## Files

### Root (cross-cutting handlers)
- `Render.js` — The sole module permitted to display visual content to the browser. All visual pipelines — DOM UI and WebGL level rendering — end here. Consumes scene graphs produced by builders and element trees from `NewUI.js`. Shader source lives in `utilities/Shaders.js` (below); `Render.js` imports its default object as `CreateShader` and calls `CreateShader.<Name>(gl)`. The CPU-side decal code stays here.

  **Frame order (`drawScene`).** `syncCanvasSize` → `blendAnimatedTextures` → clear `renderer.drawnTextures` → bind the filter target (when a filter is on) or the canvas → build `projection`, `view`, `viewProjection` and `FrustumPlanes(viewProjection)` → `passState` → `drawSkyPass` → `hideOffscreen` → build scatter buffers and void-wall lists if needed → `hideOccluded` → `collectRenderableMeshes` → void walls → **PASS A** (terrain, obstacles, `entitiesUv`, `entitiesTriplanar`) → **PASS E** decals → **PASS E2** toon ink → **PASS B** instanced scatter → **PASS B2** scatter decals → **PASS D** translucents and trigger overlay → **PASS F** filter onto the canvas → debug overlays. `passState` carries `projection`, `view`, `viewProjection`, `frustum`, `fogFull`, `colorShift`, `underwaterValue`, `cullRadius`, `nearWaterClip`, `cameraPosition`, `comic`, the sky stops and `waterTint`.

  **Mesh buckets and translucency.** `collectRenderableMeshes` skips terrain and obstacle records that aren't `mode: "default"` or whose `performance.rendering` is false, and **entities whose `performance.rendering` is false**. Entity parts split into `entitiesTranslucent` (`isTranslucentMesh` — `displayColor.a` when present, else `material.transparent`), then `entitiesUv`/`entitiesTriplanar` (keyed on `mesh.geometry.triplanar`). The translucent bucket draws in PASS D through `drawTranslucentPass`: sorted back-to-front (`sortBackToFront`), drawn with `{ depthMask: false }`, and issued by `drawSortedRuns` as runs of consecutive same-shader meshes so global order survives a mixed list. The water surface is a fixed anchor inside that pass: the sorted list is partitioned above/below `world.water.level`, the far side draws first, water second, near side last. The trigger overlay (`drawTriggerOverlay`, unculled) splits the same way: its far half draws before the water and its near half after. Without water, triggers draw whole before the translucents. The triplanar pass binds `renderer.entityTriplanarShader` (object-space triplanar sampling of the shared noise canvas). The WebGL2 context is created with `alpha: false`, so framebuffer alpha built up by translucent blending is never composited against the page.

  **Water clip.** The main mesh program has a `v_worldY` varying and a `u_waterClip` uniform (x = water level in world units, y = side kept: +1 above, −1 below, 0 keeps all; clipped fragments are discarded). `drawMeshList` sets it on every non-triplanar call, defaulting to `keepWholeMesh`. `drawScene` computes `passState.nearWaterClip` once (the camera's side of the water), which the trigger overlay halves and the ink pass read.

  **Face culling is per mesh.** `setFaceCulling(gl, cull)` enables `CULL_FACE` only when `cull` is true and `CONFIG.Performance.BackfaceCulling` is on. `drawMeshList` sets it per mesh: off for `primitive === "plane"` and for `options.cull === false`. Water (`drawWaterPass`) and the trigger overlay pass `cull: false`, and the scatter, scatter-decal and mesh-decal passes skip planes.

  **Culling.** Three gates decide `performance.rendering` (plus scatter cells' and void walls' `occluded`):
  - **Distance.** `handlers/game/Performance.js` writes `performance.rendering` once per tick for terrain meshes, obstacle records and entities.
  - **Frustum.** `hideOffscreen(sceneGraph, frustum)` turns it off for anything fully outside the frustum (`AabbOutsideFrustum`). Entities are tested with `entityRenderBounds` (every part's box, via `PointsAabb`) padded by `PERFORMANCE_SCALING.Culling.EntityPadding`. `drawDecalPass` skips hidden entities; `drawVoidWalls` draws only the on-screen void walls.
  - **Occlusion** (`OCCLUSION` section; runs only when `CONFIG.Performance.OcclusionCulling` is on). `chooseBlockers` picks up to `Culling.BlockerBudget` solid boxes from terrain `occluder` records (see builder.md's `NewTerrain.js`), largest on screen first, and keeps last run's useful blockers ranked first. `hideOccluded` projects each terrain mesh, obstacle, entity, scatter cell and void wall's box (grown by a distance-scaled margin) and hides it when a blocker's screen rectangle and hull contain it and it lies past every blocker face facing the camera (`ProjectBoxCorners`, `CornersInsideHull`, `BeyondFrontFaces`). Objects are hidden through `performance.rendering`; scatter cells and void walls through an `occluded` flag cleared at the next run. A run that hides nothing pauses the step for a doubling window capped at `Culling.IdleBackoffMs`; moving past `ResumeDistance`, turning past `ResumeTurn` or changing camera mode ends the pause. Occlusion state lives on `renderer.occlusion`.

  **Filters.** With `CONFIG.Rendering.Filters.ToonLines` or `.Comic` on, the scene draws into `renderer.sceneTarget` (`ensureSceneTarget`: multisampled RGBA8 colour and DEPTH_COMPONENT24 renderbuffers at `FILTER_TUNING.Samples`, or 0 samples without MSAA, resized with the canvas). `resolveSceneTarget` blits it into `resolveFramebuffer` (colour and depth textures) or `edgeFramebuffer` (depth).
  - **PASS E2, ink** (`drawInkPass`, after decals and before scatter): blits scene depth, then alpha-blends ink lines where inverse view depth bends past `FILTER_TUNING.Lines.Threshold`, faded by fog. It drops ink on the far side of the water through `nearWaterClip`.
  - **PASS F, filter** (`drawFilterPass`): draws the resolved scene onto the canvas. With Comic on it posterizes (`Posterize { Levels, Strength }`) and lays halftone dots below `Halftone.Below` brightness, skipping the sky. The resolved scene depth is written through `gl_FragDepth` under `depthFunc(ALWAYS)`, and `LESS` is restored after.
  - **Comic light bands** are in every surface program, gated by the `u_comic` uniform from `passState.comic` (`configureTexturedMeshPass`): the screen-space face normal against `FILTER_TUNING.Comic.LightDirection`, stepped into `Bands` above `ShadowFloor`.

  **MSAA and flat shading.** `ensureLevelRenderer` creates the context with `antialias: !(CONFIG.Debug.All && Debug.Levels.Performance.NoMSAA)` and stores `renderer.msaa` and `renderer.flatShading` (`Debug.All && FlatShading`); both apply on the next level load. Flat shading makes every surface program output `DEBUG_COLORS.FlatShading`, and `drawWaterPass` returns early.

  **Decals are host facets.** A decal is geometry taken from its host mesh, not a projected grid. `ResolveDecalShapeCode(shape, side)` maps the host onto `DECAL_SHAPE_CODES` (`Flat`/`Sphere`/`Cylinder`/`Capsule`); cylinder `top`/`bottom` resolve `Flat`. `BuildDecalPlacementMatrix(dim, transform, side)` composes face translation × `DECAL_FACE_ROTATIONS[side]` × roll × scale in part-local space and takes the transform directly — the renderer passes `displayTransform`, the exporter `localTransform`. `SelectDecalFacets(geometry, placement, shapeCode, halfExtents, rounding, margin)` keeps every host triangle whose decal-uv bounding box overlaps the `0.5 × margin` footprint, padded by that triangle's own uv extent, and emits it whole; flat hosts short-circuit to the two-triangle placed quad (`flatDecalFacets`, ordered `[0, 2, 1, 1, 2, 3]` so the quad faces outward). The exact cut is per fragment: both decal fragment shaders share `decalSurfaceUvGLSL` and `discard` outside `[-0.5, 0.5]`. Animation therefore moves a uniform and never rebuilds geometry: `ensureDecalGeometry` caches one VAO per `(mesh, decal index)` in the `renderer.decalGeometry` `WeakMap`, built once at a footprint margin from `decalAnimationMargin` (the widest scale and offset the entity's animation tracks reach for that decal, × 1.15), or 1 for untracked and non-entity decals.

  **The decal surface map.** `DecalSurfaceUv(point, placement, shapeCode, halfExtents, rounding, referenceArc)` is the single definition of the part-local → decal-uv mapping and `decalSurfaceUvGLSL` its exact mirror; a change lands in both. Offsets are arc lengths, so a decal wraps as far as it is wide. `Flat` is a planar projection. `Sphere` — and a `Capsule` whose decal center lies on a cap — is azimuthal equidistant about the decal center, capped at one full turn. `Cylinder`, and a capsule center inside the axis band, is an axis-anchored unroll (`arc = rho · dTheta`, `rise` from `decalMeridianArc`, which continues the tube's meridian onto a capsule cap). `decalSurfaceFrame` makes the frame a true rotation; `decalAxisAngle` gives a pole vertex the center's own angle. `width`/`height` and `rho` are floored at `1e-6`. `CapsuleBand(halfExtents, rounding, y)` (exported) resolves a capsule's cap height, cylinder half-length and ray origin at a height, shared with `Simulator.js`'s `decalSurfaceNormal`. `DecalRounding(shape, primitiveOptions)` (exported) returns a capsule's `rounding` and `0` otherwise; it reaches the GLSL map as `u_rounding`. The map assumes the analytic shape of `builder/NewPrimitive.js`'s `buildSphere`/`buildCylinder`/`buildCapsule`, not their tessellation.

  **Skybox and distance fog.** A full-screen sky quad draws before all geometry (`drawSkyPass`) with `DEPTH_TEST` disabled. `skySampleGLSL` (in `Shaders.js`) is shared by the sky shader and every fogged surface program, so fog colour is *sampled from the skybox per fragment* by view-ray elevation; underwater it resolves to `world.water.tint`. Stops run horizon → zenith, evenly spaced; `fillSkyStops` writes only the live stops into a `SKY_STOP_LIMIT`-sized uniform array. The fog factor is `clamp(length(v_viewPos) / u_fogFull, 0, 1)` cubed, and `drawScene` computes `u_fogFull` as `simDistance × WorldInstances.Cull × WorldInstances.Fog × (CONFIG.Rendering.Fog[Air|Water] / 100)`, with `simDistance` read straight from `PERFORMANCE_SCALING.SimDistance.Tiers`. `applySkyUniforms` is the one place sky/water uniforms upload; `ensureFullscreenQuad` is the shared quad factory.

  **Render matrix cache.** `renderMatrixFor(mesh)` is the single accessor for a mesh's render matrix. It compares the mesh's builder-populated `renderMatrixCache` snapshot (see builder.md) against the live `displayTransform` with `CompareVector3` on all four fields and returns the cached `Float32Array` on a hit; on a miss it writes into that same array and updates the snapshot in place. Zero allocation on the hot path.

  **Void rendering is geometry, not stencil.** There is no stencil path and the context has no stencil buffer: the hole in a host is carved into its index buffer at build time by `builder/NewVoid.js`. `ensureVoidWallMeshes` gathers every relation's `voidWallMeshes` once per level and splits them by shader; `drawVoidWalls` issues the on-screen, unoccluded ones. Because carving appends vertices, `createMeshBuffers` uploads `Uint32Array` indices drawn with `gl.UNSIGNED_INT`, and `getMeshBufferKey` includes the index count so a carved mesh cannot reuse an uncarved VAO.

  **Instanced scatter.** `buildScatterInstanceBuffers` runs once per level. It measures each batch's `instanceReach` from its shared primitive geometry, groups its instances into XZ ground squares of `Culling.ScatterCellSize` (`groupInstancesIntoCells`, returning `{ start, count, aabb }` per square), uploads the grouped copy and builds one VAO per square (`buildInstancedVao` with an `instanceOffset`). Batch results carry `cells` and `primitive`. It also precomputes each batch decal's shape code, placement matrix and facet geometry (margin 1) into a `decalDraws` list with matching `cellVaos`. PASS B and `drawScatterDecalPass` issue one instanced draw per square that passes `scatterCellVisible` (within `passState.cullRadius` of the camera and not fully outside the frustum) and isn't `occluded`. `sceneGraph`'s scatter `instanceData` is not modified. `beginDecalState`/`endDecalState` share the blend state of both decal passes.

  **Scatter distance fade.** Per instance in the **vertex shader**: `scatterCullGLSL` (in `Shaders.js`) is interpolated into both scatter vertex shaders. It takes the instance origin from `instanceModel[3].xyz`, derives `fade` by `smoothstep` over the outer `Scatter.Fade` share of `u_cullRadius`, and compares it against `cullHash × 0.75`, a hash of the origin. A failing instance emits `gl_Position = vec4(0, 0, 2, 1)` and is clipped before rasterization. Survivors get `instanceAlpha = clamp((fade − cullHash) × 4, 0, 1)`, a dissolve that always reaches full opacity before `fade` reaches 1. **The block must be shared, not duplicated:** decals cull and fade in lockstep with their blade because both hash the same origin. The main scatter program folds the fade into `v_tint.a`; the premultiplied decal program multiplies the **entire** `vec4` by `v_cullAlpha`, or decals would brighten as they fade. `cullRadius` is `simDistance × Fractions.Scatter.Cull`, computed once per frame.

  **GPU texture-animation compositing.** `handlers/game/Texture.js` is a pure state machine; `blendAnimatedTextures` draws `mix(from, to, blendRatio)` into each entry's GL texture through `renderer.blendFramebuffer`. `ensureAnimatedSources` lazily creates the two source textures and recycles the outgoing `from` as the incoming `to` on each rollover (`stateEntry.pendingSurface`). It runs in `drawScene` immediately after `syncCanvasSize` and before `gl.viewport`, which restores everything it changes, so moving the call breaks it. It skips ids absent from `renderer.drawnTextures` (filled by `ensureSceneTexture`, cleared right after the blend, so this frame's binds feed the next frame's decision) and entries whose bootstrap bake hasn't landed.

  **UI stylesheet injection.** `ApplyRootStylesheet(rootId, stylesheet)` injects a converted menu's `menu.stylesheet` (see builder.md's `NewUI.js`) as one `<style id="engine-ui-style-{rootId}">` tag per root. `UI.js`'s `CreateUI` applies it and `ClearUI` removes it.

  **Render scale.** `syncCanvasSize` derives the backing store from `CONFIG.Performance.Resolution` (integer percent) and reallocates only when the scaled size changes; the canvas is CSS-sized to fill the viewport, so a sub-100 store is upscaled by the browser. Read per frame, so it applies live.

  **Logging.** `Log` calls here are `error` level on `Render` (shader compile/link failures, program and buffer creation failures, missing WebGL2), plus the scatter-buffer ready line.

  **Debug overlay categories.** `boundingBoxTypeColors`, `detailedBoundsTypeColors` and `trailTypeColors` are lookups keyed by `classifyEntityType`/`classifyEntityTrailType`. A new category needs one `CONFIG.Debug.Levels` flag plus one colour entry. `createObbLineVertices` scales each OBB axis by its own half-extent.
- `utilities/Shaders.js` — All WebGL shader source and program creation. Holds the compile/link helpers (`createLinkedProgram` binds each `attributeNames` entry to a fixed slot in declaration order), the shared GLSL chunks (`skySampleGLSL`, `decalSurfaceUvGLSL`, `scatterCullGLSL`, `comicLightGLSL`, `fullscreenVertexGLSL`), and ten program builders exported as one default object: `Program`, `EntityTriplanarProgram`, `LineProgram`, `ScatterProgram`, `DecalProgram`, `ScatterDecalProgram`, `SkyProgram`, `BlendProgram`, `InkProgram` and `FilterProgram`. `createFoggedTextureFragmentShader` builds every surface program's fragment body and, with `FlatShading` on, emits a flat-colour `main` instead.
- `Controls.js` — Input router. Attaches to DOM events and routes keyboard and pointer input to the active context (level, UI, or game passthrough). Exports `Controls` class and `StartInputRouter`. In a level, input falls through UI actions, then debug and Simulator input, then `camera/Master.js`'s `HandleCameraInput`; an unconsumed `P`/`Escape` toggles pause. The camera consumes `Escape` to release pointer lock, and `Level.js`'s `pointerlockchange` listener pauses the level when the lock is released and resumes it when the lock is taken again.
- `Sound.js` — Sound manager. Loads, plays, and controls all audio: music, SFX, voice, cutscene audio. `PlayAudio` captures its own id per call, and its `finalize` removes that id from the channel's active list.
- `UI.js` — UI state manager. Applies UI payloads, manages screen transitions, wraps `Render.js` for UI rendering and `NewUI.js` for element construction. Exposes `ConvertHTML` (over `NewUI.js`'s `ParseHTML`). `CreateUI` applies a payload's `menu.stylesheet`; `ClearUI` removes it. Engine-owned payloads that bypass `normalizePayloadSchema` (`Bootup.js`'s startup overlay, `Splash.js`'s steps, `Simulator.js`'s HUD, `Level.js`'s frame counter) author `stylesheet: null` explicitly.
- `Cutscene.js` — Cutscene handler. Drives both engine cutscenes and pre-rendered (video) cutscenes. Coordinates the `cutscene/` module group.

### handlers/game/ (in-game state handlers)
- `Level.js` — Level lifecycle and orchestration; the main game loop. `CreateLevel` awaits `MeasureRefreshRate()` right before `BuildLevel`, initializes the player and its animation runtime, prepares visual resources, then `InitializeCameraState`.

  **`Update(deltaMs)`, in order:** `UpdatePerformanceFlags` → (Simulator: `UpdateSimulator`, particles, frame tail, return) → the **collision registry pass** (`UpdateCollisionCandidates` for every entity) → `PrepareCamera` → player: `UpdatePlayer(deltaSeconds, cameraState.modeData)`, `ApplyPhysicsPipeline`, `HandleEnemyCollisions`, `HandleCollectiblePickups`, `ResolvePlayerState` → non-player entities with `performance.physics` (skipping particles with `physicsMode "none"`): movement track, then `ApplyPhysicsPipeline` → `updateParticles` → `UpdateCamera` → `ResolveEntityAnimation(player)` → frame tail (`UpdateTextureAnimation`, `syncEntityMeshes`, bounding-box refresh). The camera runs first because it decides how this step's input executes.

  **Fixed-timestep loop.** `StartLevelLoop` latches `levelLoop.uncapped` (`FrameRate === Infinity`) and `fixedTimeStep` (`1000 / UncappedSimRate` when uncapped, else `1000 / FrameRate`). Each unpaused frame averages the last 4 frame times; when that average is within 1 ms of a whole number of steps, or of an even split of one step, the accumulator gains exactly that, otherwise the real frame time (uncapped mode always adds the real time). Steps are bounded by `PERFORMANCE_SCALING.Loop.MaxSubsteps`; leftover debt is dropped by clamping the accumulator to one step, logging a `warn` on the first capped frame and an `error` after `sustainedCapFrames` (10) in a row. `RenderLevel` runs on frames that stepped, or every frame when uncapped. The frame counter (`engine-frame-counter` root, built through `CreateUI`) shows renders per second, refreshes every 500 ms, follows `CONFIG.Performance.FrameCounter` live, and is removed by `StopLevelLoop`. A `pointerlockchange` listener pauses the level when pointer lock is released and resumes it when the lock returns.

  **Scene mutation.** `SpawnIntoScene(definition, objectType, sceneGraph)` dispatches on `objectType` — entities (`ENTITY_TYPES`) through `BuildEntity` against `buildSceneSurfaceMap(sceneGraph.terrain, sceneGraph.obstacles)`, `"obstacle"` through `BuildObstacles`, `"terrain"` through `BuildTerrain` — passing the live `textureRegistry` as the `faceTextureStore` and `sceneGraph.partGeometryCache` to `BuildEntity`. Every branch funnels through `finalizeSpawn` (`AddToVisualResources`, `SyncTextureAnimation`, conditional `RefreshSceneBoundingBoxes`). `AddEntityToScene(entity, sceneGraph)` also admits entities built elsewhere, such as `Simulator.js`'s player model. `DespawnFromScene` mirrors the dispatch, accepts a record or an array, and also calls `SyncTextureAnimation`. `ResumeLevelLoop()` restores level-mode input routing (`UpdateInputEventTypes({ payloadType: "level" })`), like `CreateLevel`.

  **Particles.** `updateParticles` drives every group's lifetime once per step (splicing finished groups), skipping `follow`, `advance` and `seedDue` for groups whose `performance.physics` is false. `SpawnParticles(request, generator)` (re-exported as `ENGINE.Level.SpawnParticles`) drops a burst beyond draw distance with a `Level` warn, builds generator requests at any distance, and runs `UpdateCollisionCandidates` on new groups. `findSceneTarget(sceneGraph, id, partId)` flattens the three collections into `{ type, transform }` for the runtime validator and generator resolution. `syncEntityMeshes` calls `UpdateEntityModelFromTransform` for every non-player entity, which itself short-circuits for entities that haven't moved.
- The level camera is its own module group: see camera.md.
- `Animation.js` — Entity animation handler. `CONFIG.Performance.Animations` is a flat tier (`Disabled` returns early): `resolveCorrectionFrames` scales the per-entity correction-frame budget by `PERFORMANCE_SCALING.Animation.Entities`, clamped to 4–8 frames for the player and 0–4 for everything else.

  **The model-pose channel.** Surface-orientation easing lives here, not in `physics/`. `runtime.modelPose` (seeded by `buildModelPose` from the body) is a whole-model display transform that `resolveModelPose` advances toward `entity.transform` at `entity.modelTurnRate.air`/`.water`. `stepModelRotation` eases **in basis space** — rate-limiting the pose's up and forward with `RotateTowardVector3` and recomposing through `EulerFromBasis` — because interpolating Euler triples tears at the pitch pole. `resolveModelPose` returns the pose as a display root while it lags and `null` once settled (an `EPSILON` comparison). The pose turns about `physics/Correction.js`'s `PoseAnchor(entity)`, so a body that snaps to a new facet doesn't pop the model. `EnsureAnimationRuntime(entity)` (exported) builds the runtime on first use; `Level.js` calls it for the player at level setup so the camera can read `modelPose` from its first frame.

  `ResolveEntityAnimation` then branches three ways: with a set playing, `resolveAnimationStep` walks from the leaning root (or the model's own `rootTransform` when settled); with no set but a live lean, `clearDecorations` resets decals and colours while `resolvePoseStep` walks the rest pose under the leaning root; with neither, `clearDisplay` resets everything. `walkModelParts(model, root, visit)` is the shared traversal. Its "no set matches action" warning logs on `Level`.
- `Performance.js` — Per-instance performance flags, the collision registry and refresh-rate measurement. Exports `UpdatePerformanceFlags`, `UpdateCollisionCandidates` and `MeasureRefreshRate`.
  - **`UpdatePerformanceFlags(sceneGraph)`** runs once per tick at the top of `Level.js`'s `Update` and is the single site that measures camera distance for gating. It reads the SimDistance tier straight from `PERFORMANCE_SCALING.SimDistance.Tiers`. `performance.rendering` on terrain meshes, obstacle records and entities is a **point-to-AABB** test (`Vector3SqDistanceToAabb`) against `simDistance × WorldInstances.Cull`. Entities also get `performance.animatedTexture` (within `simDistance × TextureAnimation.StopBake`) and `performance.physics`: for a particle group, its rendering result (particles simulate as far out as they're drawn); for anything else, center distance within `simDistance`.
  - **`UpdateCollisionCandidates(entity, sceneGraph)`** qualifies an entity — the player always, others when `performance.physics`, `CONFIG.Physics.Collision.Enabled` and the entity's collision flag are on — re-poses it, and stores `BroadphaseCollectCandidates(sceneGraph, simRadiusAabb, isPlayer, type !== "particle")` on `entity.performance.collision`, or `false` when it doesn't qualify or the list is empty. Physics iterates that list (see physics.md).
  - **`MeasureRefreshRate()`** times 30 `requestAnimationFrame` gaps. If the fifth-shortest gap is under 2 ms the browser limiter is off (`Infinity`); otherwise `fastestRepeatedRate` takes the shortest gap with at least 5 gaps within 5% of it, as whole Hz, or `null` when none is found or it's under 30 Hz. The result is written to `CONFIG.Performance.RefreshRate`.

  Builders attach the flag block, so every instance carries it from construction and no consumer guards for it.
- `Enemy.js` — Enemy behaviour handler. Per-frame enemy AI and combat response through `physics/Collision.js`'s `DetectCombatOverlaps`.
- `Collectible.js` — Collectible pickup. `HandleCollectiblePickups` tests `AabbOverlap` against the player's box for collectibles whose `performance.physics` is on.
- `Boss.js` — Boss behaviour handler.
- `Simulator.js` — Simulator mode lifecycle and live preview, integrated with `Level.js` through `IsSimulatorActive` and `UpdateSimulator`. `Load(payload)` takes a cached `{ payloadType: "cached", id }` or a full definition, and resets `sceneGraph.partGeometryCache` each load. The Simulator drives the camera itself: `UpdateSimulator` calls `PrepareCamera`/`UpdateCamera` with `simulating = true` and its `followTarget`, so the camera runs plain orbitCam (see camera.md). The disc platform and framing derive from the loaded object's AABB: `spawnPlatform(sceneGraph, footprintXZ)` rebuilds the disc through `SpawnIntoScene` (cloned from `templateDisc`); `frameLoadedObject(aabb)` sets `distance`/`heightOffset` via `camera/Modes.js`'s `SetOrbitCamFraming`, each floored at the template's value (`framingFactor` 1.8 × the largest extent; `heightFraction` 0.5 × height), and sets `followTarget` to `{ transform: { position } }` at the AABB's XZ center and `min.y + height × aimHeight`. `Load` spawns the platform before an obstacle/entity so grounding has a surface, then re-seats the object on it: obstacles get a per-part shift onto the platform's top-center (`UpdateObjectWorldAabb`, `MergeAabb`, `CreateDetailedBoundsFromParts`); entities get their X/Z written onto the platform and are re-posed. Loading terrain drops the disc; anything else resizes it (`platformPadFactor` 1.6×). Generator requests are rebuilt every `Load` through `ParticleGeneratorRequests` with `physics` forced to `"none"` (`WithParticleOverride`); `clearParticles` runs first so a reload doesn't stack emitters.

  **Engine cache entries.** On the first `Start`, `cacheEngineEntries` pre-fills the cache: each `player/characters.json` character as `player.<id>` (`objectType: "player"`, unvalidated), and every terrain/obstacle and character/enemy/projectile template as a minimal `shape: "template"` ref under `template.<id>`. `Load`'s `"player"` branch builds exactly as a level does: `BuildPlayerModel` with a `rootTransform` at `(0, platformTopY, 0)`, `spawnSurfaceId: null` and `sceneGraph.spawnSurfaces`, inserted through `AddEntityToScene`, after which it is treated as an `"entity"`.

  **GLB export.** `Download()` (bound to `[E]`, exposed as `ENGINE.Simulator.Download`) writes the loaded object as a self-contained glTF 2.0 `.glb` named `${loadedId}.glb`, by hand, in the `GLB EXPORT` block. `exportMeshList` reads `simulatorRuntime.builtObject` and mirrors the renderer's mode rules, so void and invisible meshes never reach the writer. Each mesh becomes one node whose `matrix` is `CreateModelMatrix(mesh.transform)`. `meshPrimitiveSpans` splits a mesh into primitives by `faceTextureGroups`; `buildMeshVertices` de-indexes with flat normals and bakes triplanar UVs on the CPU from the dominant axis. Decals export from the renderer's own implementation: `buildDecalVertices` takes `SelectDecalFacets` (margin 1) with `BuildDecalPlacementMatrix(…, localTransform, …)`, drops facets whose uv winding differs from the facet nearest the decal center (a sphere's antipodal fold), subdivides each kept facet into barycentric sub-triangles until the linear uv error is under `decalUvTolerance` (0.05, at most `decalMaxSubdivision` 16), clips them to the `[-0.5, 0.5]` square (`clipToDecalSquare`), and lifts each vertex along the analytic `decalSurfaceNormal` by `decalSurfaceOffset + index × decalLayerStep`. Textures come from the live `textureRegistry` (`encodeTextureImage` picks `OPAQUE`/`MASK`/`BLEND`); decal materials are always `BLEND`. `writeGlbBinary` 4-aligns every binary view.
- `Texture.js` — Animated texture state manager. A pure state machine; `Render.js`'s `blendAnimatedTextures` does the GPU crossfade. Per animated texture entry (`createAnimationStateEntry`) it tracks a hold/blend cycle across `fromSurface`/`toSurface`/`readySurface`, and each frame advances a resumable `bakeJob` (`BeginTextureBake`/`AdvanceNoiseBake`) budgeted by elapsed milliseconds, so a slow frame draws more and the bake still lands on schedule. Exports `InitializeTextureAnimation`, `UpdateTextureAnimation` and `SyncTextureAnimation` (called from `Level.js`'s `finalizeSpawn` and `DespawnFromScene`), which registers new animated textures and rebuilds every entry's owners.

  **Two gates, one per cost.** *Distance gates the CPU bake.* A bake runs when the texture is worn by an entity flagged `performance.animatedTexture` (`nearEntityTextureIDs`, once per frame) **or** any static owner mesh is within `simDistance × TextureAnimation.StopBake` (point-to-AABB). Static owners come from `assignOwnerMeshes`, which walks `NewTexture.js`'s `ForEachTexturedMesh` with entities excluded. Only baking is gated: the clock, the hold → blend transition and `blendRatio` keep running, so a far but visible texture finishes its crossfade. *Visibility gates the GPU blend* (`renderer.drawnTextures`, above). A scatter batch texture registers by batch id rather than through a mesh, so it has no owner and never bakes (see `DEFERRED.md`).

### handlers/menu/ (menu state handlers)
- `Splash.js` — Splash screen sequence management. Coordinates with `Bootup.js` for the startup splash flow via `AcceptSplashPayload` and `ApplySplashScreenSequence`.
- `LoadScreen.js` — Loading screen display logic.
- `Credits.js` — Credits screen UI and behaviour.

## Boundaries
**Called by:** `Bootup.js` and `ini.js` for initialization; game code via the `ENGINE` API at runtime.
**Calls into:** `camera/`, `player/`, `physics/`, `builder/`, `cutscene/`, `math/`, `core/`.
**Does not:** Implement physics math, mesh construction, or vector math directly — these are always delegated to the appropriate group.

## Invariants
- `Render.js` is the exclusive rendering boundary. No other module writes to the DOM or WebGL context for display purposes; `utilities/Shaders.js` only builds programs for it.
- `Level.js` owns the main game loop (`requestAnimationFrame`) and is the single entry point for all per-frame game state updates.
- `Performance.js` is the single site that measures distance for gating and the single writer of `entity.performance.collision`; consumers read the flags and lists instead of recomputing.
- `SpawnParticles` is **push-only**, and must stay so. `SendEvent` dispatches synchronously from inside `Update`'s `sceneGraph.entities.forEach`, so a game's handler — and any `ENGINE.Level.*` call it makes — runs re-entrantly mid-iteration. `forEach` skips elements appended during iteration, which makes a push safe; a splice would not be.
- A **runtime** particle spawn must register its textures (`finalizeSpawn` with objectType `"entity"`); the reseed path inside `updateParticles` must not. Particle parts carry the literal `"none"` texture id, which only reaches the registry at build time when a level-authored generator exists. `"particle"` is never a valid `objectType` here.
- `ENGINE` (assembled by `ini.js`) is the exclusive interface between game code and the engine.
- `handlers/game/Level.js` is the direct caller of `physics/Master.js`. There is no intermediary physics handler.
- The model-pose channel is **one-way**. `Animation.js` reads `entity.transform` and eases a display-only pose; physics, collision and the ground probe keep the exact orientation.
- `blendAnimatedTextures` must run before `gl.viewport` in `drawScene`, and `renderer.drawnTextures` must be cleared immediately after it: clearing at end of frame would gate every animated texture off, and not clearing would gate nothing.
