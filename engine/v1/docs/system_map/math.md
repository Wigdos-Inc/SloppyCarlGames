# math/ — Shared Math Layer

## Responsibility
Pure, stateless math utilities available to any engine module without restriction. Provides typed unit conversion primitives, 3D vector operations, matrix composition, physics force math, collision and geometry helpers, and curve utilities. Together with `core/`, this is the engine's global helper layer — anything may import from it.

## Files
- `Utilities.js` — `Unit` and `UnitVector3` classes: typed value containers with conversion methods (`toRadians`, `toDegrees`, `toCNU`, `toWorldUnit`, `clone`) plus in-place component writers (`set`, `add`, `min`, `max` on `UnitVector3`). `CNU_SCALE` constant (fixed at development time). Conversion functions: `DegreesToRadians`, `RadiansToDegrees`, `CNUtoWorldUnit`, `WorldUnitToCNU`. Utility functions: `Clamp`, `Clamp01`, `Lerp`, `SmoothStep`, `ToNumber`. `BestMatchOf(array, condition, currentBest, storage)` (the author's version) returns the item that wins a pairwise `condition(entry, best, storage)` comparison; `math/Collision.js`'s soup contact and `builder/NewEntity.js`'s face-to-axis alignment use it.
- `Vector3.js` — 3D vector operations: `AddVector3`, `SubtractVector3`, `MultiplyVector3`, `DivideVector3`, `ScaleVector3`, `DotVector3`, `CrossVector3`, `LerpVector3`, `AbsoluteVector3`, `ClampVector3`, `CloneVector3`, `ToVector3`, `MinVector3`, `MaxVector3`, `RotateByEuler`, `Vector3Distance`, `Vector3Length`, `Vector3Sq`, `ResolveVector3Axis`, and `MinAxisVector3` (the index of the smallest component). Exports `WORLD_NORMALS` (canonical axis directions).
  - **Direction easing.** `RotateTowardVector3(from, to, maxStep)` is the shared unit-direction rate limiter: a slerp step toward `to` capped at `maxStep` radians, returning `to` once within reach and picking an arbitrary perpendicular when antiparallel. Every heading, reference-normal, model-pose and camera-roll ease in the engine turns on it. `AngleBetweenVector3(a, b)` is the radians between unit vectors.
  - **Carrying headings.** `TransportVector3(v, from, to)` applies the minimal rotation carrying unit `from` onto unit `to` to `v`; `player/Movement.js`'s carried heading and physics' crest turn use it. `AzimuthTurnVector3(from, to)` returns the yaw-only Euler `{ x: 0, y, z: 0 }` between two vectors' headings, zeroed past a quarter turn and **zero when either vector has no horizontal component** (`hypot(x, z) <= EPSILON`). `camera/Master.js`'s loop tracking and Movement's wall carry use it to separate a tube's bend from loop travel.
  - **Arrays.** `Vector3ToArray` flattens a vector to `[x, y, z]`. `ArrayToVector3(array, index, multiplied)` reads one back: with `multiplied`, `index` is a vertex in a flat xyz array (`index * 3`); without it, the three values are read from `index` directly. Every vertex read in builder/ and handlers/ goes through it.
  - **Shared predicates.** `CompareVector3(a, b, method)` compares components directly, and `Vector3SqDistanceToAabb(point, aabb)` returns the squared point-to-box distance (0 inside), shared by `handlers/game/Performance.js` and `handlers/game/Texture.js`.
- `Matrix.js` — 4×4 matrix creation (`CreateIdentityMatrix`, `CreateModelMatrix`, `CreateRenderMatrix`) and transform composition. `ComposeEulerRotations(parentRotation, localRotation)` multiplies both triples as `Ry·Rx·Rz` rotation matrices and decomposes the product back to Euler through the private `decomposeEulerRows(m, degenerateRoll)`, taking roll on the axis at gimbal lock. `EulerFromBasis(right, up, forward, degenerateRoll)` is the second entry into that decomposition: the Euler triple for an orthonormal basis, used by `SurfaceAlignedRotation` and `handlers/game/Animation.js`'s `stepModelRotation`. `builder/NewEntity.js`'s `ComposeTransform` and the animation walk nest part rotations through it, since adding triples is only correct for single-axis chains. `MultiplyMatrix4` is the shared 4×4 multiply. `TransformPointByMatrix(point, matrix)` transforms a point (moved here from `builder/NewObject.js`). `InvertAffineMatrix(m)` inverts a model matrix; the occlusion blockers use it for host-local space. `FrustumPlanes(matrix)` returns the six inward-facing walls of a projection × view matrix, each `[x, y, z, offset]`. `CreateRenderMatrixCache(transform)` is a pure factory returning `{ matrix: Float32Array, position, pivot, rotation, scale }` — the render matrix plus a by-value snapshot of exactly the four fields `CreateRenderMatrix` reads, colocated so the two stay in lockstep. Builders populate it on every mesh carrying a `displayTransform`; `handlers/Render.js`'s `renderMatrixFor` is the sole reader.
- `Collision.js` — Geometry math in labelled sections. No state, no engine-state dependencies.
  - **Narrowphase.** `NarrowphaseContact(boundsA, boundsB)` dispatches on the first two letters of each shape type (`spsp`, `caaa`, `aatr`, `voca`, …) to one private contact function per pair, reversing via `invertContact` for the mirrored order. A compound sphere iterates its spheres and keeps the deepest. `OffsetDetailedBounds(bounds, offset)` moves any collider shape. Contact functions with no outside importer are private and lowerCamelCase.
  - **Soup contacts.** The four sphere/capsule soup and void-wall contacts are one-line calls to the private `deepestContactInBox(triangles, box, contactWith)`, which skips triangles outside a query box (`SegmentQueryBox(start, end, radius)`, tested by `TriangleInQueryBox`, both exported). Void-wall contacts respond on the geometric normal, not `triangle.normal`, while their one-sided gate still tests `triangle.normal`. `aabbTriangleSetContact` runs SAT of an AABB against the overlapping triangles as one hull, picking the facing triangle with `BestMatchOf`; `aabbTriangleSoupContact` (two-sided) and `aabbVoidWallContact` (one-sided) wrap it.
  - **Contact response and velocity.** `ApplyAcceleration`, `ApplyDeceleration`, `ClampVelocity`, `ProjectOntoPlane`, `HorizontalApproach` and `SlideAlongContacts(velocity, displacement, contacts, fold)`, which turns velocity across a walkable `fold` instead of cutting it. Shared by Movement, physics and the camera.
  - **Ground probe and alignment.** `PointAabbFaceGap`/`PointObbFaceGap` find ground only through a face the point is over (outside exactly one axis); `NearestFrontTriangle` finds the nearest up-facing soup triangle by true distance. `SurfaceAlignedRotation(alignedUp, facing, rotation, onBack)` builds an orthonormal basis from the plane-projected facing (falling back to uphill, then to the heading from `rotation.y`), turns it −90° about its right axis when `onBack`, and decomposes it through `EulerFromBasis`.
  - **Boxes.** `AabbOverlap` (optional strictness), `ExpandAabbY`, `AabbOutsideFrustum(planes, aabb, padding)`, `AabbCenter`/`AabbHalfExtents` (plain vectors), `SphereFromAabb(aabb, inscribed)`, `CapsuleFromAabb`, `ObbFromAabb` and `PointsAabb(points, min, max, transform, skip)` (the shared min/max fold).
  - **Triangles.** `ClosestPointOnTriangle`, `TriangleNormal` (zero when degenerate), `TriangleArea`, `TriangleCentroid`, `TriangleAabb` and `TriangleDistanceSq`.
  - **Solid queries** (build-time predicates over closed meshes, used by `builder/NewVoid.js`). `PointInsideMesh(point, triangles)` is ray-parity along the off-axis `parityRayDirection`, through the per-triangle `insideRayCrosses`. `BuildTriangleGrid(triangles, triangleAabbs)` splits a mesh's bounds into equal cells (`CARVE_GRID_TRIANGLES_PER_CELL` triangles each, roughly); `TriangleGridCandidates(grid, aabb)` returns the triangle indices in the cells a box touches; `PointInsideTriangleGrid(point, grid)` answers like `PointInsideMesh` but tests only the cells the ray passes. `SplitPolygonByPlane(polygon, normal, offset)` returns `[front, back]` corner lists, or `null` when the plane doesn't cut the polygon. `MeshesIntersect(solidA, solidB)` takes cutting solids: containment through the other solid's grid, then the private `edgesCrossMesh` against grid candidates.
  - **Blockers** (occlusion culling). `InscribedBox(primitive, dimensions, primitiveOptions)` is the largest box inside a shape before scale, or `null` for shapes with none. `VoidCutBoxes(solidTriangles, centerline, inverse)` gives the boxes that hold a void in a host's space (one per tube stretch). `SolidBoxes(inner, cuts, scale, minSize)` subtracts the cuts, merges touching pieces, drops scraps and narrow pieces, and keeps the largest 8. `AabbLargestFace`, `ProjectBoxCorners`, `ConvexHull2D`, `CornersInsideHull` and `BeyondFrontFaces` are the per-frame screen and depth tests `handlers/Render.js`'s `hideOccluded` runs.
  - **Swept and ray tests.** `SweptAABB` and `SweptSphereBounds`, plus `RayAABBIntersect`, `RaySphereIntersect`, `RayOBBIntersect`, `RayCapsuleIntersect`, `RayTriangleIntersect`, `RayTriangleSoupIntersect` (skips triangles outside the segment's box when given a finite `maxDistance`), `RayAABBDetailedBoundsIntersect` and `RayDetailedBoundsIntersect`.

  **Ray-hit contract.** Every ray-hit result carries `{ hit, t, normal, inside }`. `inside` marks an **exit hit**: the ray began within the volume. `RayAABBIntersect` sets it in its origin-inside branch (which returns the exit distance); `RaySphereIntersect` and `RayCapsuleIntersect`'s body roots set it when the near root is behind the origin; `RayOBBIntersect` propagates it; triangles always report `false`. The field is present on every result, so consumers read a guaranteed field.
- `Forces.js` — Pure force math: `ComputeGravity`, `ComputeResistance`, `ComputeBuoyancy`, `ComputeStepVelocity`, `ComputeSubmergence`. Operates on numeric inputs plus `CONFIG.Physics` constants; no entity state. `ComputeStepVelocity.scalar(v, forces, dt, vertical)` applies whichever of `gravity`/`buoyancy`/`resistance` `forces` carries (each only when its `CONFIG.Physics.*.Enabled` is on, otherwise warn-logged on `Level`), then optional floatiness smoothing; `sim` runs it per axis. `scalar`'s sole engine caller is `player/Movement.js`'s jump-launch solver.
- `Curves.js` — Curve and frame utilities backing the node-chain `tube` primitive. `ApplyEasing(name, t)` resolves `linear`, `easeIn`, `easeOut` or `easeInOut`. `SampleConnectorCenterline(startCenter, forward, endCenter, backward, smoothness, segments)` returns `segments + 1` centerline points spanning one tube connector: a cubic Bézier with forward-aligned handles, so it departs along `forward` and arrives along `-backward` for any corner angle. The handle length is the circular-arc one for the connector's turn θ: `d = chord · (2/3)·tan(θ/4)/sin(θ/2)`, or `chord/3` when straight. Each sample blends that cubic against a hard-corner hairpin through `cornerM` by `smoothness`. `ParallelTransportFrames(points, initialNormal)` returns a twist-free `{ tangent, normal, binormal }` per point by double reflection (Wang et al. 2008).

## Boundaries
**Called by:** Any engine module freely — no access restrictions.
**Calls into:** `math/` modules import each other; `core/` (`meta.js` for `EPSILON`/`Log`, `config.js` for `CONFIG` and `CARVE_GRID_TRIANGLES_PER_CELL`).
**Does not:** Hold mutable state, perform side effects other than `Forces.js`'s disabled-stage warnings, or import from handlers, physics, player, builder, camera or cutscene.

## Invariants
- All exports are pure functions or immutable constants, except `Unit`/`UnitVector3`, which are value-holding class instances.
- `Unit` and `UnitVector3` are the canonical typed-value containers for all measurement values. They are instanced exactly once per value at a system entry point; downstream code operates on existing instances.
- `CNU_SCALE` is fixed at development time and does not change at runtime.
- `math/` never calls `Unit`/`UnitVector3` methods on its inputs; it works through the Vector3 helpers, so games can pass plain vectors.
- `math/Collision.js` is geometry math only — no entity state or physics state. Its contacts, probes and blockers are what `physics/` and `handlers/Render.js` compose.
- `math/Forces.js` is pure math only — force assembly with entity context lives in `physics/Forces.js`.
- `RayAABBDetailedBoundsIntersect` passes the **caller's** `maxDistance` to the narrowphase, never `broadHit.t`: detailed bounds sit inside the broad AABB, so capping at the entry `t` could only reject real hits. It short-circuits to the broad hit for `aabb` bounds and copies `broadHit.inside` onto a triangle-soup result.
- `math/Curves.js` operates on plain `{x,y,z}` numeric vectors, not `Unit`/`UnitVector3`.
- `SampleConnectorCenterline` needs no zero-length guard: the handle length multiplies the chord, so a zero chord degenerates without dividing by zero.
- The connector's smooth handle length is turn-angle aware but **symmetric**, so asymmetric corners still overshoot. The hard-corner point `cornerM` keeps fixed `0.667 × chord` handles.
