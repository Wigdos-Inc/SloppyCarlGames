# physics/ — Physics Pipeline

## Responsibility
Computes and applies physics for moving entities each frame: gravity, buoyancy, fluid resistance, water currents, collision detection, and surface correction. The pipeline is externally driven — handlers pass entity state in and the pipeline mutates it in place. physics/ does not manage its own update loop.

## Files
- `Master.js` — Physics pipeline orchestrator. `ApplyPhysicsPipeline` is the external entry point called per physics-active entity per frame. Coordinates detection, force application, correction, and model sync internally. Its sole export is `ApplyPhysicsPipeline`.

  **Force stages and Movement's hooks.** Gravity is scaled by `entity.gravityScale` (1 by default; `player/Movement.js` lowers it while coasting a loop lock). The resistance stage is skipped while `entity.dragFree`. After the floatiness stage, a positive `entity.staticFriction` cancels the along-surface part of the tick's vertical change (gravity, buoyancy, floatiness) up to `staticFriction × dt` via `ApplyDeceleration`, so an idle player on walkable footing holds still on a slope. All three are written by Movement every step.

  **The correction loop.** `runPhysicsLoop` snapshots `frameStart` — `referenceNormal` and the last surface stood on (`physicsRuntime.groundSurfaceId`) — before the correction loop. Two per-step values come from kept footing (grounded and not `launched`). `groundReach` (snap tolerance + |displacement| × sin(`MaxAngleDelta.Ground`)) feeds `ProbeGroundContact` and `ApplyGroundSnap`. A `fold` context (`{ normal: surfaceNormal, minCos }`) feeds both `ResolveCollisions` calls, so velocity turns across walkable folds instead of being cut. `contactGrace` counts down once per step, and `launched` clears once velocity along `alignedUp` is ≤ `EPSILON`. The player's triggers from the final overlap pass are stored in `playerState.activeTriggers`, which `camera/Master.js` reads for camera triggers. The loop does **not** zero `transform.rotation.x`/`.z` at the top of the step, so the collider carries the previous frame's surface tilt through the whole step; `ApplyPlayerSurfaceOrientation` runs once at the end, after `ApplyGroundSnap` and the final overlap pass, and writes all three rotation axes. Grounding is derived once after the loop (`entity.grounded = ResolveGrounded(entity)`). The other once-per-frame tails are `UpdateGripDemand` and the `referenceNormal` update: contact-less frames past the contact grace rotate it toward world up by `ReferenceReleaseStep(deltaSeconds)`, and a `"walkable"` contact that actually moved adopts `surfaceNormal` outright. `physicsRuntime.groundSurfaceId` is written only when the probe hits, so it holds the last surface through misses. It reuses the candidate array `DetectCurrentPhysicsOverlaps` returns for the player's `ProbeGroundContact`, re-gathering via `BroadphaseCollectCandidates` only when that iteration's correction actually moved the entity (`overlapResolution.changedPosition`) — the broadphase ran before the correction, so only a move invalidates it.
- `Collision.js` — Broadphase and narrowphase collision detection against scene geometry. Trigger overlap detection. Scene spatial queries. Exports `GetSimDistanceValue`, which reads the active tier out of `PERFORMANCE_SCALING.SimDistance.Tiers` in `core/config.js` (Low 50 / Medium 100 / High 150 / Ultra 250 CNU) — the tiers are `Unit` instances declared there, and the accessor returns the shared instance rather than building one, so a per-entity per-frame gate costs a property read. `IsBeyondSimDistance(viewerPosition, targetPosition)` is the shared gate wrapping that threshold — a `null` viewer opts out entirely, since a payload may carry no player. `IsBeyondSimDistance` is now consumed once per tick by `handlers/game/Performance.js` (which resolves it into `entity.performance.physics` for every entity) and by `builder/NewParticles.js`'s generation gate; `Level.js`'s entity pass, `Collectible.js`'s pickup pass and `DetectCombatOverlaps` read the resolved boolean instead of recomputing. `DetectCombatOverlaps(playerState, entities)` correspondingly takes no `simRadius`/`cameraPos` arguments. Also exports `GetEntityPhysicsFlags(entity)`, which resolves `entity.character.physics` for the player and `entity.movement.physics` for everything else.

  Two scene queries are exported for use outside the pipeline. `BroadphaseCollectCandidates(sceneGraph, aabb, includeTriggers, includeEntities)` is exported so `camera/Master.js` can broadphase its obstruction rays. `IsPointInSuppressingVoid(point, candidateId, voids)` (formerly the private `isGroundSupportInVoid`, body unchanged) answers whether a world point on a host lies inside a void that suppresses it — used by `ProbeGroundContact` for ground support and by the camera for obstruction.

  `ProbeGroundContact(entity, sceneGraph, groundReach, candidates, frameStart)` takes its candidate list as a parameter: its two full scans of `sceneGraph.terrain` and `sceneGraph.obstacles` collapsed into one loop over the already-filtered candidates, dropping the repeated `AabbOverlap`. `DetectCurrentPhysicsOverlaps` retains and returns the array it built (`candidates`, an empty array on the collision-disabled early return) so the caller can hand it straight back.

  **Ground probe shape.** The probe point is `entity.collision.rest.groundCapsule`'s lower cap center placed by the transform — scaled, rotated, translated, the same order `placeBoundsForShape` seats a narrowphase collider (see builder.md) — so grounding always uses the rest-pose capsule whatever collider the entity declares. `maxDist` is the scaled radius plus `groundReach`. Three helpers take the probe point as a first parameter rather than closing over it: `tryAABB` and `tryOBB` ground **only through a face the probe is over** — a hit needs the probe outside exactly one of the box's axes, so an embedded probe (0 axes) or one past an edge or corner (2+) returns null, `t` is that axis's excess and the normal is that face's axis — and `trySoup` (nearest up-facing triangle by true distance via `ClosestPointOnTriangle`, with `reachesTriangle` rejecting back faces and returning squared distance). Every accepted candidate passes through `pushHit(t, normal, surfaceId, sticky)`, which classifies it on arrival via `Correction.js`'s `ClassifySurface(frameStart.referenceNormal, normal, entity.surfaceContact, entity.underwater, speedRatio, entity.gripDemand)` and **drops anything classed `"wall"`** — a wall never grounds, so it never reaches the ranking. `speedRatio` is the player's tangent speed over `maxSpeed`; a `sticky` surface (the `levelObject.sticky` flag, read from mesh `meta` for terrain and from the record for obstacles) and every non-player entity pass `Infinity`, so they always grip. Surviving hits carry `t`, `normal`, `contact` and `surfaceId`; both void-wall soups (`floorBounds` and `wallBounds`) are probed the same way and report the **void's own id** (e.g. `cave-tunnel`) and the void's own `sticky` flag, not the host's.

  Selection is **class first, then distance**: a `"walkable"` hit beats a `"sliding"` one outright, then the nearest `t` wins; the **coupled** surface — `entity.physicsRuntime.groundSurfaceId` — only breaks ties within `EPSILON`. The return is `{ hit, normal, contact, restDelta, surfaceId }`, where `restDelta = radius - t` is the move **along the contact normal** that seats the cap center at its rest distance from the surface. There is no support point: `ApplyGroundSnap` consumes `restDelta` directly.

  **Void suppression is per-contact.** `isVoidCancelled` cancels when the entity AABB center is inside the void solid, or when the contact point stepped `contactMaterialProbe` (0.05 cnu) back along the contact normal into the host is inside it; a contact carrying no point falls back to the whole-body test. Both suppression tests attempt `NarrowphaseTest` against `detailedBounds` first and fall back to exact `PointInsideMesh` ray-parity containment against the void's `solidTriangles` — an additional accept path, so suppression can only widen. Both swept branches of `DetectPhysicsCollisions` evaluate it at the **end-of-frame** position (`vel`), not at the contact instant, where the body still sits outside the void. Void wall candidates carry a `sourceType` (`"terrain"`/`"obstacle"`) stamped by `BroadphaseCollectCandidates` and carried onto the pooled solid result, so `ResolveCollisions` resolves `sourceType || type` for its surface test and `buildGroundContact` reports the source category rather than the raw `voidWall` type.
- `Correction.js` — Surface classification and post-collision position/orientation adjustment. Exports `ClassifySurface`, `ApplySurfaceCorrection`, `ApplyGroundSnap`, `ApplyPlayerSurfaceOrientation`, `PoseAnchor`, `ResolveGrounded`, `ReferenceReleaseStep`, `UpdateGripDemand` and `CORRECTION_DISABLED` — the one frozen all-false result object, reused by `Master.js`'s `noResult.correction`.

  **Surface classification.** `ClassifySurface(referenceNormal, candidate, currentContact, underwater, speedRatio, gripDemand)` is pure and returns `"walkable" | "sliding" | "wall"`. `angleLimitsFor(underwater)` picks the `Air` or `Water` half of `CONFIG.Physics.Correction.MaxAngleDelta`, each carrying `Ground`, `Sliding` and `Recover`. Anything within `FlatSnapDegrees` of world up is walkable outright. Otherwise a candidate no steeper than the reference (`candidate.y >= referenceNormal.y`) is judged on **absolute incline** alone, and a candidate steeper than the reference is judged on the **delta** between the two — walkable within the walkable limit, sliding within `Sliding`, wall beyond. The walkable limit is `Recover` rather than `Ground` while `currentContact === "sliding"`, which stops a slide from re-latching to walking on the same angle that started it. Past the `Ground` incline, a would-be walkable contact slides when `speedRatio < gripDemand`. It is called from `physics/Collision.js`'s ground probe, not from this file's own correction path.

  **Grip demand.** `UpdateGripDemand(entity, groundContact, deltaSeconds)` runs once per step and only while the probe hits (it holds while airborne). It moves `entity.gripDemand` toward `max(0, MinGripSpeed × (cos(Ground) − normal.y) / (cos(Ground) + 1))` at `MinGripSpeed / GROUNDING.GripRampMs` — none at the `Ground` incline, the full `MinGripSpeed` upside down — so a run up a wall or into a loop has to carry speed, and a stop there slides.

  `ReferenceReleaseStep(deltaSeconds)` is the radians the grounding reference may decay toward world up in one frame, from `CONFIG.Physics.Correction.ReferenceReleaseRate`; `Master.js` is its sole caller.

  **`ResolveGrounded(entity)` is the single grounding authority** — a pure derivation, not an assignment: `surfaceContact === "walkable"`, minus a launch veto (`launched && DotVector3(velocity, alignedUp) > EPSILON` — measured along the contact's own up, not world `velocity.y`), minus buoyancy exceeding gravity. `launched` is set by a jump or knockback and cleared by `runPhysicsLoop`. No other site writes `grounded`.

  `ApplySurfaceCorrection(playerState, groundContact, frameStart)` consumes the probe's `contact` verbatim. It publishes `surfaceContact` and writes `surfaceNormal` (always the real normal) alongside `alignedUp` (world up within `FlatSnapDegrees`, the normal otherwise). Velocity is **pinned** to the surface only with kept footing — grounded last step, or the contact's `surfaceId` equal to `frameStart.surfaceId` — and not `launched`: then the whole normal component is removed, otherwise only an into-surface component. Over a walkable crest the velocity is first turned onto the new facet with `TransportVector3`, and a pinned lift-off on a walkable contact keeps its speed. A miss returns `resetSurfaceState`: contact `"none"`, and unless `launched`, a **contact grace** (`GROUNDING.ContactGraceMs`) during which `alignedUp`, `surfaceNormal` and the whole rotation hold; after it, both vectors return to world up. Velocity is untouched either way.

  `ApplyGroundSnap` is gated on `playerState.grounded` and moves **along the contact normal** by the probe's `restDelta`, comparing `|restDelta|` against the tolerance — a perpendicular offset throughout, not a vertical one.

  **Orientation is solved from a full basis.** `solveAlignmentRotation(alignedUp, facing, rotation, onBack)` projects `facing` (the world-space heading `player/Movement.js` maintains) onto the surface plane, builds an orthonormal `(right, up, forward)` from it and `alignedUp`, and hands the triple to `math/Matrix.js`'s `EulerFromBasis` with `rotation.z` as the pole roll seed — so yaw, pitch and roll all come out of one decomposition rather than yaw being frozen and pitch/roll solved against it. A planar facing shorter than `minPlanarFacing` (0.05) has collapsed onto the normal: it falls back to the uphill direction, then to the flat heading read off `rotation.y`. `onBack` (contact `"sliding"`) turns the basis −90° about its own right axis by passing `(right, -forward, alignedUp)`. `ApplyPlayerSurfaceOrientation` does nothing during the contact grace. Otherwise it writes the whole triple through `rotation.set(solved)` and pivots about `PoseAnchor(entity)` — the scaled rest ground-capsule cap center while touching a surface, the rest-AABB center when releasing one — translating by the difference in that anchor before and after the rotation, since rotating about the transform origin alone swings the cap off the surface the probe just accepted. `handlers/game/Animation.js` turns the eased model pose about the same anchor. It eases nothing: the value here is exact, because the collider, the ground probe and the pivot all key off it. The *visible* easing is `handlers/game/Animation.js`'s model-pose channel (see handlers.md).
- `Forces.js` — Engine-shaped force assembly. Reads entity state and `CONFIG` to produce gravity, buoyancy, resistance, and submergence force vectors. Delegates pure math to `math/Forces.js`.
- `Current.js` — Movement velocity adjustments for entities inside underwater current volumes.

## Boundaries
**Called by:** `handlers/game/Level.js` — calls `ApplyPhysicsPipeline` directly from `Master.js` each frame. No intermediary Physics handler file exists in the current source. `Collision.js`'s scene queries are additionally imported by `handlers/game/Performance.js` (`GetSimDistanceValue`, `IsBeyondSimDistance`), `camera/Master.js` (`BroadphaseCollectCandidates`, `IsPointInSuppressingVoid`) and `builder/NewVoid.js` (`NarrowphaseTest`). `Correction.js`'s `PoseAnchor` is imported by `handlers/game/Animation.js`.  
**Calls into:** `math/` (Vector3, Utilities, Collision, Matrix, Forces); `core/` (config, meta); `player/Master.js` (`TriggerPlayerRespawnSequence`) for player respawn; `builder/NewEntity.js` (`UpdateEntityModelFromTransform`) for post-physics model sync, used identically for the player and every non-player entity since the player build was unified onto the entity pipeline. The ground probe no longer derives its own capsule: it reads the frozen `entity.collision.rest.groundCapsule` and places it by the transform.  
**Does not:** Read user input, manage its own update loop, or drive rendering.

## Invariants
- `SimDistance` is the **single distance authority** in the engine. Every other reach is a fraction of it declared in `PERFORMANCE_SCALING.SimDistance.Fractions` (scatter cull radius, animated-texture bake cutoff, world-instance render cull, and fog saturation as a fraction of that cull), and the tier value itself gates enemy activation, collectible pickup, entity updates and particle spawn range. There is no second distance setting — a subsystem needing its own reach adds a fraction there rather than a config field, and raising a tier therefore moves gameplay range and visual range together.
- `ApplyPhysicsPipeline` is called once per frame per physics-active entity, in dependency order determined by `Level.js`.
- Displacement (`ScaleVector3(entity.velocity, deltaSeconds)`) is computed **outside** every physics-flag check, so zeroing an entity's stage flags does not make the pipeline inert — a non-zero `entity.velocity` still sweeps. Anything that owns an entity's motion itself must be skipped at the `Level.js` layer rather than relying on flags; particle `physicsMode "none"` is the current case.
- Particles are excluded from entity-vs-entity collision in **both directions**, and the two exclusions are separate. `BroadphaseCollectCandidates` skips `type === "particle"` when building candidates (a particle never obstructs anything), and its `includeEntities` parameter — which both call sites derive as `entity.type !== "particle"` — skips the entity collection entirely when the *querying* entity is a particle. Only the second stops a burst from destroying itself: a runtime burst spawns at its emitter's transform origin, so without it the emitter is a solid the particle is born inside, and `ResolveCollisions` strips the whole launch velocity along the contact normal on the first frame. Particles still collide with terrain, obstacles and void walls, which is correct — a ground normal opposes only downward motion and ejects an upward-moving particle out of the surface.
- Entity state is mutated in place by the pipeline; results are not returned as new objects.
- `math/Forces.js` contains pure numeric math; `physics/Forces.js` wraps it with entity and config context.
- `math/Collision.js` contains pure geometry math; `physics/Collision.js` contains detection logic with scene state.
- The player and non-player entities share one model-sync path (`UpdateEntityModelFromTransform`) and one collision-bounds shape (`aabb`/`physics`/`hurtbox`/`hitbox`); `Master.js` branches on `isPlayer` only for player-only stages (input-driven correction source, ground-contact probing, respawn, action-state events), not for model or collision-bounds representation.
- Colliders are **frozen at build time and only placed thereafter**. `entity.collision.rest` holds the local-space shapes captured from the rest pose (see builder.md's `captureRestCollision`); nothing in physics re-fits a collider from the posed model. `ProbeGroundContact` (`Collision.js`, player-only) reads `rest.groundCapsule` and places it by the transform; it neither re-derives a capsule nor reads a stored world one. It never gathers its own candidates either: the caller supplies them, and is responsible for handing over a set gathered against the entity's *current* position. The player's swept-solid detection path (`DetectPhysicsCollisions`) still differs from the non-player path (`DetectCurrentPhysicsOverlaps`) in how it gates candidates before the swept test — see `DEFERRED.md`.
- **The ground probe is the sole authority on surface contact, and `physicsRuntime.groundSurfaceId` is its memory.** `runPhysicsLoop` writes the probe's `surfaceId` back after every hit (never on a miss), the probe uses it to break distance ties, and `ApplySurfaceCorrection` reads it through `frameStart` for kept footing. No other site decides which of several overlapping surfaces an entity is standing on; `camera/` reads it to look up ramps and loop surfaces.
- **Physics never imports camera.** Camera-driven behaviour reaches physics only through entity fields Movement writes (`gravityScale`, `dragFree`, `staticFriction`).
- **`grounded` is derived, never assigned.** `ResolveGrounded(entity)` is the only expression that produces it and `runPhysicsLoop` the only site that applies it, once per frame after the correction loop. `surfaceContact` is the input, `grounded` the conclusion — a consumer that wants to know *what* the entity is standing on reads `surfaceContact` (`"walkable"`/`"sliding"`/`"wall"`/`"none"`), not `grounded`, which answers only whether it is standing.
- **`referenceNormal` is the last walked surface, and it is written once per frame.** `frameStart` freezes it for the whole correction loop so a mid-frame walk cannot feed back into the classification that produced it. Adoption is instant (a `"walkable"` contact that moved takes `surfaceNormal` outright); release eases toward world up at `ReferenceReleaseRate`. The asymmetry is deliberate — an eased adoption would let the reference lag behind a surface the entity is demonstrably standing on.
- **`physics/` writes exact orientation only.** `ApplyPlayerSurfaceOrientation` solves `transform.rotation` from `alignedUp` with no rate limiting, because the collider, ground probe and pivot anchor all read that rotation the same frame. Visual smoothing of the whole model is `handlers/game/Animation.js`'s model-pose channel, which eases a separate display transform and never writes back here.
- Penetration pushout resolves **along the detected contact**: `DetectCurrentPhysicsOverlaps` takes `pushNormal`/`pushDepth` from the narrowphase contact produced by the entity's declared collider, never from a second axis-aligned narrowphase. The whole support-point chain that once backed this (`resolveBoundsSupportPoint`, `resolveContactSupportPoint`, `resolvePushSupportPoint`) is gone, along with `fillSolidResult`'s `candidateBounds` parameter — ground seating is `restDelta` from the probe.
