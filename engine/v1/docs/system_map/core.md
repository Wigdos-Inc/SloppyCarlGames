# core/ — Engine Foundation

## Responsibility
The foundation layer. Provides logging, event dispatch, session persistence, global configuration, payload validation/normalization, and the public ENGINE API surface. Everything else in the engine depends on core/; core/ itself has minimal reverse dependencies. Two files participate in the startup chain outside the core/ directory: `Bootup.js` at the engine root (entry point) and `canonSchemas.json` embedded inside core/.

## Files
- `config.js` — Runtime configuration singleton. Physics constants (gravity, buoyancy, resistance), debug flags, volume levels, performance settings, camera FOV, custom event toggles. `PERFORMANCE.Resolution` is an integer percent (default `100`, matching the `CAMERA.Sensitivity` convention) controlling the WebGL canvas backing-store scale; read per frame by `Render.js`'s `syncCanvasSize` (see handlers.md), so it applies live without a level restart. Imports `Unit` from `math/Utilities.js` to instance typed physical constants at load time. `RENDERING.Fog` is `{ Air, Water }`, integer percentages (valid 20–100) scaling how far distance fog takes to saturate; above 100 the saturation point passes the cull radius and geometry pops in. `SKY_STOP_LIMIT` (10) is a standalone export outside both `CONFIG` and `PERFORMANCE_SCALING` — the maximum authorable skybox gradient stops, and the array size of the `u_skyStops` uniform in `Render.js`. `DEBUG.LEVELS.BoundingBox` and `.DetailedBounds` each carry a `Void` category (default `false`) covering a void's own volume plus the void walls and open faces derived from it; `.BoundingBox`/`.DetailedBounds`/`.Trails` each carry a `Particle` category (default `false`) alongside `Entity`/`Enemy`/etc. — particle groups are ordinary `sceneGraph.entities` (see builder.md) and previously fell through to whichever bucket a `type.includes(...)` classifier ladder matched first, burying real entities under per-particle debug output. `PERFORMANCE` is the user-facing tier surface: `Scatter: { Density, Quality }`, flat `Particles`, flat `SimDistance`, flat `Animations`, plus numeric `FrameRate` and `Resolution`. Tier values are capitalized strings — `Disabled`/`Low`/`Medium`/`High` for `Scatter.Density`, `Particles` and `Animations`; `Low`/`Medium`/`High`/`Ultra` for `SimDistance`; `Low`/`Medium`/`High` for `Scatter.Quality`. The two without a `Disabled` position have none by design: `SimDistance` is the simulation authority, and `Quality` selects what a scatter blade is *made of* (`Density` is what controls how many exist). This is a distinct vocabulary from the lowercase `complexity` payload field (`canonSchemas.json`, `allowedValues: ["low","medium","high",""]`), which is schema-authored content, not a config tier, and is not to be "matched" to it — `NewScatter.js` lowercases `Scatter.Quality` at its own call site to index tier maps, which is a local read, not a shared vocabulary.

  **`PERFORMANCE_SCALING`** — a second export holding every engine-internal constant those tiers scale, keyed to mirror the settings. `SimDistance.Tiers` are `Unit` instances in CNU (Low 50 / Medium 100 / High 150 / Ultra 250), read through `physics/Collision.js`'s `GetSimDistanceValue`. `SimDistance.Fractions` derives every other reach from that one distance: `Scatter.Cull` (0.70 of sim distance) with `Scatter.Fade` (0.40 **of the cull radius**, recorded as the width of the dissolve band rather than the radius fraction where it starts, so the shader reads `u_cullRadius * (1.0 - Fade)` and the relationship stays visible at the point of use); `TextureAnimation.StopBake` (0.60 of sim distance); and `WorldInstances` — `Cull` (1.5 of sim distance, the render reach for terrain meshes, obstacle records and entities, resolved once per tick by `handlers/game/Performance.js`) with `Fog` (0.90 **of that cull radius**, the fraction of the render reach at which distance fog saturates). `Density.Scatter` (`{ Disabled: 0, Low: 0.25, Medium: 0.50, High: 1 }`) and `Density.Particles` (`{ Disabled: 0, Low: 0.50, Medium: 0.80, High: 1 }`) are separate curves, kept apart so scatter population and particle count tune independently — they now hold different values, so folding them together would change both. `Animation.Entities` (the frame-correction budget) is on its own steeper `{ 0, 0.25, 0.50, 1 }` curve and must **not** be folded into the `Density` curves either. `Loop.MaxSubsteps` (4) bounds how many fixed-timestep physics ticks one frame may run before the level loop drops its remaining debt (see handlers.md's `Level.js`) — it replaced a frame-time clamp. Consumers index these tables directly at their call sites; there are no wrapper accessors.
- `ini.js` — Builds and returns the public `ENGINE` API object. Imports from handlers, player, and math and assembles them into namespaced groups. Called once by `Bootup.js`; the result is assigned to `globalThis.ENGINE`. Top-level shape: `Log`, `Config`, `Cache` (direct); `Meta` (log replay, event dispatch, session helpers, pointer-lock read/request, `CNU_SCALE`, `Version` — the published engine version, authored as a literal directly in the frozen `Meta` namespace rather than imported from `meta.js`); `Input` (input router, pointer-lock read/request/release, `Cursor`); `Controls`; `Cutscene`; `Startup`; `UI`; `Audio`; `Level` (lifecycle functions + `Player` API); `Math` (sub-namespaced: `Convert`, `Vector3` — `AddVector3, DivideVector3, MultiplyVector3, ScaleVector3, DotVector3` —, `Instancing`, `Physics` — `ComputeGravity, ComputeResistance, ComputeBuoyancy, ComputeStepVelocity, ComputeSubmergence` —); `Simulator`; `Blueprints`. `Blueprints` is the authored (pre-instancing) shape of engine-owned template JSON — player characters, terrain/obstacle templates, character/enemy/projectile templates, scatter — for the external Simulator App; it is the `raw` clone returned by `builder/templates/Instance.js`'s `InstanceEngineTemplates()`, which `ini.js` calls directly (no longer imports the template JSON files itself). Because `raw` is the authored shape, quality-tiered scatter fields surface as tier maps: `ENGINE.Blueprints.Scatter.grass.parts[0].primitive` returns `{ high: "cylinder", medium: "cube", low: "plane" }`, not a string. That is the intended contract — a consumer reading blueprints sees what the template file contains, not a resolution that varies with a performance setting.
- `meta.js` — Engine-wide utilities: `Log` (channel-aware, source-aware logging with session persistence and duplicate suppression), `SendEvent` (CustomEvent dispatch to `window`), session storage helpers (`PushToSession`/`ReadFromSession`), `Cache` (runtime state cache for UI, Level, Cutscene payloads), `Cursor`, `Wait`, `ExitGame`, `IsPointerLocked`, `RequestPointerLock`, `ReleasePointerLock`. Also exports constants `EPSILON`, `ENTITY_TYPES`, and the `SetEngineInitialized` lifecycle flag setter.
- `validate.js` — Validates incoming game payloads against `canonSchemas.json`. Returns structured error arrays without throwing. Imports `isTemplateRef` from `normalize.js` (single shared discriminator, not redefined locally) to branch object lists (`validateObjectList`), `entityBlueprints` bucket entries, and `ValidateSimulatorPayload`'s definition onto the `templateObjectRef`/`templateEntityRef` schemas instead of `levelObject`/`levelEntityBlueprint` when a raw entry's `shape` is `"template"`/`"blueprint"`. Template id existence is not checked here — that happens once downstream in `normalize.js`; `validate.js` only checks the ref's own shape is well-formed. `validateSkybox(rawWorld, path)` is the one hand-written structural check outside the generic schema pass: `world.skybox.color` is required and its *shape follows `mode`* — an array in `"gradient"`, an object in `"fill"` — which a single `dataType` cannot express, which is why the field carries no schema entry at all.
- `normalize.js` — Normalizes validated payload values: resolves aliases, applies fallbacks, instances `Unit`/`UnitVector3` from raw numbers. Runs a `hoistObjectColor` pre-pass before `normalizePayloadSchema` on `LevelPayload` (terrain objects, obstacles, entities, entity blueprint model parts) and `SimulatorPayload` (definition and definition.model.parts): if a node carries a root-level `color` field, it is moved into `texture.generated.primary` before schema processing, so game payloads may use a top-level `object.color` authored name while the internal `primary`/`secondary` contract is preserved; skipped for template references (`isTemplateRef(item)` true), whose `color` is a direct ref-level override, not a field to hoist. Imports character templates from `player/` and texture templates from `builder/templates/` for canonicalization lookups (approved exception in MODULE_GROUPS.md), plus (for the template-reference system below) all five `builder/templates/` template collections. Canonicalizes the otherwise-opaque `primitiveOptions` bag at this boundary so `builder/NewObject.js` needs no guards. `normalizeTubeOptions` instances the root `thickness` as a cnu `Unit`, coerces `curved` and `solid` to bools (fallback `false`) and clamps `smoothness` to `[0,1]` (fallback `0`), then maps every entry of `nodes[]` through `normalizeTubeNode`, which validates against the `tubeNode` schema and instances `dimensions`/`localPosition` as cnu `UnitVector3`, `localRotation` as degrees→radians, and `thickness` as a cnu `Unit`. `normalizeRampOptions` does the equivalent for `ramp-simple`/`ramp-complex` (selected by the `isRampShape` predicate), turning the authored-degrees `angle` into a radian `Unit` via the `rampOptions` canon schema — before this, `angle` was the one primitive option read as raw radians straight off the payload. Both are wired shape-conditionally from `normalizePart` and `normalizeLevelObject`. The Simulator blueprint-merge path re-hydrates both after `structuredClone` strips the class prototypes, reading `localRotation` and `angle` back as `"radians"` (already converted) rather than degrees.

  **Void solidity gate.** Void classification is ray-parity based downstream (see math.md's solid queries), so a void must be a closed solid. `openPrimitiveShapes` holds the only open primitive (`plane`); `hasOpenPrimitive` checks a single-shape object or any of its parts, and `normalizeLevelObject` warns and returns `null` for a `mode: "void"` object built from one, dropping it before the builder ever sees it.

  **World skybox and water.** `world.water` (`level`, nullable, and `tint`) replaces the former flat `world.waterLevel`; the water clamp against `deathBarrierY`/`height` runs on the new path and re-instances the clamped value as a cnu `Unit`. `world.skybox` carries a `mode` (`"fill"` | `"gradient"`) plus a `color` that is **absent from the schema deliberately** — no schema field can validate as both an object and an array — so `resolveSkyStops(rawSkybox, mode)` reads it off the raw payload and writes `world.skybox.stops`, an array of `{r,g,b,a}` stops running horizon→zenith. `normalizeSkyStop` fills any missing channel from `defaultSkyStop` with a warning. `fill` collapses to two identical stops, so the renderer never branches on `mode`, and an empty gradient falls back to the same doubled default.

  **Particle generator normalization.** Any part or object may carry an optional `particle: { id, position, overrides }` field declaring a level-authored particle generator. `normalizeParticle(particle, label)` is the single boundary helper: it returns `null` unchanged, validates `particle.id` against the `particles` entry in `templateCollections` (warn-and-drop the whole generator on an unknown id, mirroring `normalizeObjectTemplateRef`'s behaviour for template refs), then instances `particle.position` as a cnu `UnitVector3` and `particle.overrides.velocity` likewise when present. It is called from four mutually exclusive sites — `normalizePart`, `normalizeLevelObject`, `normalizeObjectTemplateRef`, and `normalizeTemplatePartOverrides` — so no part is ever normalized twice. `mergeBlueprintWithOverride` rehydrates `particle.position` and `particle.overrides.velocity` alongside its other Unit-space fields after `structuredClone` strips the class prototypes. Because `normalizePart` is shared, entity blueprint parts and player model parts accept the field too, even though only terrain and obstacle meshes are swept for generators at build time.

  **Decal texture normalization.** `normalizeDecalTexture` resolves `levelCustomTexture.texture`/`levelDecalSource.texture` through the shared `decalTexture` schema. `decal.color` folds onto `texture.primary` and `decal.texture.color` onto `texture.secondary` via the same `foldColorAlias` path objects use; decal-level `color` is deleted after folding, so `primary`/`secondary` remain the only canonical colour surface. `resolveTextureId` reads the `deprecatedAliases` `__meta` key to resolve `baseTextureID`→`id` independently of `deprecated: true`. `markMutableDecals` reads the resolved rest tint from `texture.primary`.

  **Menu stylesheet preload.** `MenuPayload` scans `menu.stylesheet` (verbatim `<style>` block contents, see builder.md's `NewUI.js` HTML conversion) for `url()` references via a module-scope `cssUrlPattern`, so CSS-authored background images preload the same way inline `object`/`texture` images do.

  **Runtime request normalization.** A second, smaller boundary sits alongside the full-payload one, for fire-and-forget requests issued by a running game rather than whole payloads. `normalize.js` exposes a `Runtime` object as a key on its default export (so it inherits the same "only `validate.js` imports the default export" posture as `LevelPayload` and friends); `validate.js` exposes a matching exported `ValidateRuntime`. Each carries per-request-type entry functions — only `Particles` today — plus a `helpers` sub-object for internals meant to serve future request types. The contract is **validate → normalize → build → insert**, where normalization is invoked *by* the validator and never called separately, and nothing is returned to the game: success, warnings and rejections are all communicated by `Log`. `Runtime.helpers.cloneRequest` walks the schema first and `structuredClone`s the result, so unknown keys are dropped before cloning (a request carrying a callback would otherwise throw `DataCloneError`) and the caller's nested objects are never aliased into engine state.

  **Template reference normalization** (boundary lookups only — resolves ids and instances override fields, never constructs the full template definition; actual template resolution happens in `builder/NewTemplate.js` at build time). Exports `isTemplateRef(value)` (true when `value.shape` is `"template"` or `"blueprint"`) — the single discriminator used by both `validate.js` and `normalize.js` to branch payload entries onto the template-ref path instead of the ordinary object/blueprint path. `normalizeObjectTemplateRef(rawObject, ctx, collection, label)` validates the referenced `terrain`/`obstacle` template id exists (warn-and-drop otherwise), instances `position`/`rotation`/`scale`/`texture` override fields, and normalizes `parts` as **per-part overrides** (`normalizeTemplatePartOverrides`, keyed by part id, validated against the template's actual part id set — unknown ids warn-and-drop). `normalizeEntityTemplateRef(rawRef, ctx, label)` does the equivalent for `character`/`enemy`/`projectile` template refs living in an `entityBlueprints` bucket entry, instancing `model.rootTransform` with null-aware fields (an unset override field stays `null`, letting the template value win downstream) via the shared `normalizeRootTransform(transform, requireAll)` helper (also used by `normalizeBlueprint`/`normalizeOverride` with `requireAll: true`, where every field is always instanced). `mergeTemplateRefEntity` (called from `mergeBlueprintWithOverride` when `blueprint.shape === "template"`) merges an `entities`-list spawn override onto a template-ref blueprint — supports `id`/`blueprintId`/`hp`/`collisionOverride`/`dialogue`/`spawnSurfaceId`/`rootTransform` overrides; `movement`/`velocity`/`attacks`/`animations` overrides are not supported for template-ref spawns (template values always win). Both `LevelPayload`'s terrain/obstacle/entityBlueprints mapping and `SimulatorPayload` branch per-entry on `isTemplateRef` to call the ref normalizer instead of `normalizeLevelObject`/`normalizeBlueprint`; `SimulatorPayload` additionally warn-and-nulls a terrain template ref outright (the Simulator's single-mesh terrain spawn path cannot round-trip multi-part terrain).
- `canonSchemas.json` — Schema registry. Defines field types, allowed values, ranges, fallbacks, and aliases for all payload structures that pass through validate/normalize. `menu.stylesheet` (`isExpected: false`, fallback `null`) carries verbatim `<style>` block contents produced by HTML-converted UI payloads, so hand-authored screens with no such field stay warn-free; `Render.js` injects it as a per-root `<style>` tag (see handlers.md). `generatedTexture`'s color surface is `color` (object-level `levelPart.color`/`levelObject.color` alongside `generatedTexture.color` — the modern, non-deprecated authoring name, folded onto `primary` by `normalize.js`'s `foldColorAlias`) plus the older `primary`/`secondary` rgba override fields, now `deprecated: true` but still fully supported; all three replace the template default colors at canvas-generation time rather than via shader tint. `generatedTexture.compositeMode` (`"replace"` / `"overlay"` / `null`, fallback `null`) selects how a translucent secondary paints over the primary base — see `NewTexture.js`'s `resolveReplace` in builder.md. `generatedTexture.opacity` was removed; transparency derives from `primary.a`/`secondary.a` instead. `levelCustomTexture.texture`/`levelDecalSource.texture` resolve through a shared `decalTexture` schema root carrying the full `generatedTexture` field set (`id`, `shape`, `compositeMode`, `primary`, `secondary`, `color`, `density`, `speckSize`, `animated`, `holdTimeSpeed`, `blendTimeSpeed`), with both `color` fallbacks `null`; `animated` (fallback `false`) opts a shape decal into the preset's animation cycle (`decalAnimationDefinition` in builder.md). `detail` survives as a deprecated alias of `texture`, `baseTextureID` as an alias of `id` — expressed through a `deprecatedAliases` `__meta` key, distinct from `deprecated: true` (which fires on canonical-name matches too and cannot express an alias-only deprecation). `level.world.waterLevel` is gone, replaced by a `water` block (`level`, a nullable number, and `tint`, whose fallback is a populated rgba); `skybox` is `isRequired` and declares only `mode` — its `color` has no schema entry at all, since the field is an object in `"fill"` mode and an array in `"gradient"`, which one `dataType` cannot cover (`validate.js`'s `validateSkybox` and `normalize.js`'s `resolveSkyStops` handle it instead). `rampOptions` is the canon schema for `ramp-simple`/`ramp-complex` `primitiveOptions`: a single `angle` field in degrees, fallback `0`, meaning "derive the rise from `dimensions.y`". The `tube` options bag has **no** schema root of its own — only `tubeNode` does — so `tube`'s `solid` flag is handled ad hoc in `normalizeTubeOptions` alongside `curved`/`smoothness`. The `tubeNode` entry defines one node of a `tube` bone chain: `dimensions` (x/z cross-section opening radii; `y` is unused and present only for schema uniformity), `thickness`, `localPosition` (an offset expressed **in the previous node's rotated frame**), `localRotation`, `curved`, and `smoothness`. `templateObjectRef` and `templateEntityRef` are the schemas for `shape: "template"`/`"blueprint"` payload entries (terrain/obstacles, and entity-blueprint-bucket entries respectively): every overridable field (scale, color, texture, collisionShape, mode; rootTransform, hp, collisionOverride) falls back to `null` so the resolver can distinguish "not overridden" from an authored value, and both carry a `parts` array of per-part override entries (id + overridable fields only, no shape/geometry fields — composition and `repeat` are template-authored and have no payload schema representation at all). The `particle` node (a level-authored particle generator: `id`, `position`, and an `overrides` sub-object) is declared in five places, byte-identical in each: `levelPart`, `levelObject`, `templateObjectRef` root, `templateObjectRef.parts.__entry`, and `templateEntityRef.model.parts.__entry`. Its `overrides` sub-object enumerates exactly six keys — `count` (ranged 1–50), `spread` (`narrow`/`medium`/`wide`/`max`, the last a 180° full-sphere cone), `physics`, `color`, `velocity`, `duration` — with every nested child declared, so `normalizePayloadSchema` guarantees a fully-keyed object and the builder's null-sentinel merge can never see `undefined`. `color` is `{ start: {r,g,b,a}, variance, end: {r,g,b} | null }` — `start` an rgba spawn color, `variance` one 0–1 jitter shared by r/g/b (never per-channel, which would produce random hue drift), and `end` a nullable rgb-only color at end of decay (`null` = constant; `end` has no `a`, since the colour timeline never touches alpha — that is owned by `duration.mode`). The particle's `part` prototype and `amount` are template-owned and have no override schema; a particle's physics stage flags are not authored at all, being derived from `physics` (the mode) at build time in `builder/NewParticles.js`. A sixth, structurally identical copy of the same `overrides` shape (including `color`) lives on `particleRequest`, the root schema backing runtime `ENGINE.Level.SpawnParticles` requests (`id`, aliased to `templateId`; `position`, absolute in burst mode or an offset from `target` in generator mode; `target: { id, type, partId }`, `null` for a one-shot burst; `overrides`) — validated/normalized by the separate Runtime boundary described below, not the full-payload one.
- `engine/v1/Bootup.js` — Engine entry point. Exports `StartEngine()`. Runs browser context validation, calls `Initialize()` from `ini.js`, attaches `PlayIntroCinematic` to the ENGINE object, assigns ENGINE to `globalThis`, runs the startup overlay, splash sequence, and fires `UI_REQUEST` to signal the game.

## Boundaries
**Called by:** `Bootup.js` calls `ini.js`. Any engine module may import `meta.js` and `config.js`. Handlers call `validate.js` and `normalize.js` at payload entry points.  
**Calls into:** `math/Utilities.js` (`config.js`, `normalize.js` import `Unit`/`UnitVector3`); `math/Vector3.js` (`normalize.js` imports `CloneVector3`); `builder/templates/Instance.js` (`ini.js` calls `InstanceEngineTemplates()` for `Blueprints`). `ini.js` imports from handlers, player, and math to assemble the API surface — this is a one-time assembly import, not an ongoing dependency.  
**Does not:** Contain game-specific logic, rendering code, or physics calculations.

## Invariants
- `Log` is callable from any engine module at any time, including before full initialization.
- `Cache` is initialized from `sessionStorage` at module load and holds last-known UI, Level, and Cutscene payloads across same-tab navigation.
- `CONFIG` is a singleton. No module replaces or re-imports it with different values.
- `validate.js` never throws — it returns error arrays. Callers check results before proceeding.
- The runtime-request boundary never reaches into the scene itself. `core/` cannot import `handlers/`, so a request needing scene state (currently only a particle generator's target) receives an **id → data resolver function** as an argument from the calling handler. The validator calls it and reads only flat primitives, so no builder-output contract enters `core/`; passing `sceneGraph` directly would violate that. A resolver rather than a pre-resolved value also defers the lookup until the schema has proven there is an id to look up.
- `normalize.js` produces `Unit`/`UnitVector3` instances. Downstream modules receive pre-instanced values and must not re-instance them (see UNIT_INSTANCING.md).
- `canonSchemas.json` is the single source of truth for allowed payload field names, types, and defaults.
- `globalThis.ENGINE` is set once by `Bootup.js` at startup and is the exclusive game-facing API surface.
